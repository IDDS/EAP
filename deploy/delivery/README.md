# EAP 私有化试点交付入口

交付档位：**有实施支持的企业私有化试点**。先核对 `release.json`，再选择下面的操作路径。该清单固定前后端镜像、数据库版本和能力边界；不把测试通过或 Pod Ready 等同于生产交付完成。

2026-10-22 已完成固定基础镜像的构建和定向发布，后端压缩层合计由约 5.40 GB 降至 203 MB，前端由约 67.8 MB 降至 22.1 MB；应用受测产物保持。[本轮验收及限制](../../docs/evidence/clean-images-20261022/README.md)。

本目录的集群操作和测试只在授权的远程 Linux 运维节点运行，本机仅编辑、打包和核对摘要。仓库连接约定见根目录 `AGENTS.md`；不在交付包中保存连接密码、Secret 内容、令牌或用户会话。

## 选择正确的入口

| 场景 | 操作入口 | 完成标准 |
| --- | --- | --- |
| 查看当前版本和支持范围 | `python3 eapctl.py check-release`、`release.json` | 对齐产品档位、两个应用镜像和 Schema；运行程序另按实际实例版本核对 |
| 已有环境版本检查 | `python3 eapctl.py inspect --namespace eap` | 应用镜像和 Deployment 就绪条件一致；继续完成 HTTP、登录和业务验收 |
| 汇总运维诊断 | `python3 eapctl.py diagnose --namespace eap --output /path/to/diagnostics/new-check` | 生成带摘要的只读诊断包，区分故障与未核实；见[诊断说明](../../docs/OPERATIONS_DIAGNOSTICS.md) |
| 审阅诊断包保留 | `python3 eapctl.py plan-diagnostic-retention --root /path/to/diagnostics --days 14 --keep 3` | 校验两个文件摘要、按命名空间保留最新报告；只列候选，不执行删除 |
| 核对受测源码 | `python3 eapctl.py verify-source --root /path/to/source --source-manifest /path/to/tested-source-manifest.json` | 所列文件摘要一致；额外文件、依赖和测试报告另行核对 |
| 从受测产物构建应用镜像 | [固定基础镜像构建](images/README.md)、`image_build.py` | 独立摘要绑定 JAR/dist、固定基础层、独立探针及部署后验收；不叠加旧应用镜像 |
| 准备应用升级 | `python3 eapctl.py plan-upgrade backend --target REGISTRY/IMAGE@sha256:DIGEST`，前端同理 | 输出固定原 UID/resourceVersion/镜像的 CAS 补丁；工具不执行补丁，不自动重试 |
| 数据库或身份恢复 | [认证恢复合同](../../docs/AUTH_PERSISTENCE.md)及当前数据库恢复方案 | 在隔离环境验证原主体、签名键、任务和预算；不得用重新初始化替代恢复 |
| 全新环境首次安装 | [JWT 控制台首次安装](install/README.md)、`bootstrap.py` | 已有独立空 MySQL/IdP 的环境中创建控制台；继续验证真实登录、持久化与运行系统接入 |

`inspect` 只读取指定 Deployment，不读取 Secret 内容，也不访问模型和业务工具。输出 Secret 引用名称，便于实施人员核对依赖；它不检查 Secret 是否存在或内容是否正确。`plan-upgrade` 是可审阅的操作计划，不能替代测试、数据备份与业务排空。后端计划采用 `Recreate` 避免两个版本的任务写者重叠；必须事先接受短暂维护窗口，并在结束后按原策略恢复。前端保留既有就绪探针和滚动策略。

## 首次安装前的环境确认

1. 确定客户及项目范围。可按[项目独立部署](../../docs/PROJECT_ISOLATION.md)使用专属数据库、JWT声明及运行空间；项目IdP、RBAC/网络与业务仍需逐项验收，不声明同库多租户SaaS隔离。
2. 确定 MySQL、持久卷、备份保存位置和恢复负责人；确认可用空间、连接限制及恢复点。
3. 确定企业 IdP、issuer、audience、PKCE 客户端、角色映射与访问域名。沿用 `PlatformPermission`，前端只读取 `/me` 能力。
4. 确定 Substrate 兼容版本、运行池、镜像仓库、网关路由和实例身份配送；新环境不要使用现有 PoC 的地址和旧实例凭据。
5. 在集群建立引用的 Secret；模型凭据只交给网关，实例通过原身份协议调用。
6. 为试点明确业务数据范围、工具读写权限、预算、负责人、成功标准与故障处置流程。

## 升级与回退次序

1. 固定受测源码清单、前后端和运行程序镜像摘要、数据库版本与兼容性说明。运行程序默认值升级不等于旧实例迁移。
2. 预检旧版本、依赖、磁盘和当前活跃派发。除确认节点没有 `DiskPressure`，还应按 kubelet 的 `nodefs/imagefs` 驱逐阈值，为镜像解包和浏览器验收预留临时空间。保留数据库及认证的可验证恢复点，确认维护窗口。
3. 生成并审阅 CAS 升级计划。环境 UID、版本或镜像变化时重新核对，不移除前置断言。
4. 单次执行已核验的补丁。请求结果不明时查询原 Deployment，不能无条件重放。
5. 后端确认旧 Pod 消失、目标 imageID、Schema 和 `/actuator/health`；前端使用 [HTTP 就绪合同](../../docs/FRONTEND_HTTP_READINESS.md)核对 `/index.html`、`/version.json` 和稳定窗口。
6. 验证四类角色、原执行记录、权限、预算和关键业务路径；记录成功与失败证据。
7. 应用回退必须先确认旧程序与当前 Schema 兼容。不可逆数据迁移需专门恢复方案，不能只回退镜像。恢复或回退不得把 UNKNOWN 改成成功或重新派发。

测试报告、镜像载荷及构建日志保存后，按该批次登记的 UID 清理已完成的临时 Pod，避免累积到归档阶段。节点驱逐属于环境失败，必须保留原因并恢复空间后使用相同受测产物继续；不能记成代码验收通过，也不应重复发布已完成的组件。

## 四个交付验收旅程

首次使用由具备任务运行能力的操作者与具备内容查看能力的验收者共同完成。先用公开样例材料验证流程；客户数据、私有遥测及代码不得发送到未经授权的外部服务。

1. 在“智能体目录”创建 Agent，进入“部署”，选择当前环境可用的零代码运行程序。检查实例身份、允许的模型、预算和运行版本。
2. 在“团队与计划”组织成员、分配步骤；或在“工作流编排”设置节点和交接。需要结构化结果时，在计划步骤或工作流节点配置“结果契约”；提交前保存，执行时冻结。
3. 提交前核对目标、输入、预算及外部工具效果范围。首次验收使用新建任务，保留平台返回的原执行编号。
4. 从首页“跟进任务”进入全部执行记录，以任务类型、状态、时间或原编号查找本次执行。团队计划和工作流进入原执行详情，独立异步任务进入其原任务详情，对话读取本人原回执。
5. 验收者打开步骤结果，分别核对流程状态、结构结论、业务要求和关联观测。缺少数据、未配置验收及 UNKNOWN 都不得记为成功。
6. 记录结果及待处理事项。出现 UNKNOWN 时先查询原效果并交接负责人；普通工具是否支持恢复、取消或补偿，应以该工具合同为准。案例归档后不重新派发原任务以补截图或验证。

| 旅程 | 验收内容 | 当前状态 |
| --- | --- | --- |
| 首次部署 | 未参与开发的实施人员在新环境按交付包安装、登录并完成依赖预检 | 已提供控制台安装器；同集群新命名空间验收见安装说明，独立实施与客户集群待验收 |
| 首次任务 | EAP 创建 Agent/团队、配置预算、派发任务、读取原结果和关联观测 | 已有有界样例证据；客户真实系统接入待指定 |
| 异常处置 | 从任务工作台定位原执行、查询原效果、区分费用与资源状态并交接负责人 | 已有受控计数核验；通用业务工具处置和工单闭环待完成 |
| 备份恢复 | 隔离环境恢复身份、业务数据、预算与执行历史，核对 RPO/RTO | 已有认证有界恢复；整体灾备和定期备份待完成 |

正式生产交付还需完成资源范围授权、生产认证配置、TLS、定期备份、跨故障域恢复、容量与长稳验收。目标并发、数据保留期限、RPO/RTO 必须由客户需求确定，不能由现有单次演示推断。
