# 工单只读查验：隔离合成样例

这是工单试点的远程隔离验证材料，**不是 EAP 生产连接器，也未接入任何真实工单系统**。`fixture_lookup.py` 只能连接本机回环地址上的合成 HTTP 服务，按受限的合成编号发送一次 GET；测试服务中角色仅为模拟标记，不是企业认证或权限实现。`fixture_draft.py` 按模拟状态生成固定的人工核对建议，将工单内容作为不可信证据与建议分开；查询未确认时不生成建议。样例不调用模型、执行建议、写工单或发通知，也不证明建议的业务质量。

结果区分 `FOUND`、`NOT_VISIBLE`、`ACCESS_DENIED`、`AMBIGUOUS`、`INVALID_RESPONSE` 和 `UNAVAILABLE`；除 `FOUND` 外不返回工单内容。找不到可见记录不能证明工单不存在，接口超时、歧义或权限不足也不能证明原操作未提交。客户端不跟随重定向、不重试，严格限制响应大小和字段。每次查询均重新取数，不沿用上一次结果；记录的时间是客户端发起查询时间，不是业务系统的更新时间。

在远程隔离测试环境执行：

```sh
cd examples/ticket-assistance
python3 -m unittest -v test_fixture_lookup test_fixture_draft
```

正式接入须依据具体系统的版本、接口与身份重新设计和验证，包括 TLS、网络出口、字段级权限、数据留存及真实业务可见性；不应直接把此样例接到真实业务系统。试点范围与验收见 [工单查询与辅助处理](../../docs/TICKETING_ASSISTANCE_PILOT.md)。

`workflow_fixture.py` 提供仅供隔离测试使用的模拟 Runtime 和合成工单服务。远程 `TicketAssistanceFixtureIT` 使用真实 EAP 工作流执行器、本地安全规则和 H2 内存数据库，验证查询结果交给草稿节点、普通执行元数据隐藏正文、找不到记录时不派发草稿，以及包含规则关键词的合成正文在进入草稿节点前被拦截；三种情况均无工单写入。安全事件不额外保存受测正文，但工作流步骤仍会保存已查询的输出。现有安全规则采用固定关键词匹配，不能据此推断可识别所有敏感内容或提示注入。测试还使用模拟 JWT 经实际权限过滤链验证四角色及匿名请求；这不验证 JWT 签名、真实登录或目标工单系统的授权。该测试显式运行 `*IT`，不属于默认后端测试套件；样例没有部署到 EAP。

合成工作流使用 `EAP_JSON_V2` 结果契约，要求查询节点输出的 `lookupConfirmed` 为 `true` 才交接草稿。查询任务完成只表示查询尝试已返回；找不到可见记录、权限拒绝、结果歧义和服务不可用均返回 `false`，工作流在结果契约处停止，受内容权限保护的原始输出保留具体查询结果。普通执行元数据不包含具体查询结果，操作员不能读取输出，治理管理员可读取。此门禁依赖合成查询组件据查询结果正确生成布尔值，不验证组件是否可信、记录是否真实或目标系统授权；模型未参与。
