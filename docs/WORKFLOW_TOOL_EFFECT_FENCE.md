# 新工作流受控计数的效果提交屏障

本阶段属于调度、Agent调优、权限治理主线的执行责任加固，针对新登记受控计数工具根。主线仍未全部完成。

V65只新增workflow_tool_effect_roots，不改旧根/操作/查询记录。新工作流登记持久查询之前取得共享scope锁和工作流锁；首次登记使用无原操作、无历史查询的根，绑定原运行和owner/epoch，保存该根后允许同一运行登记后续原工具步骤。另一运行/轮次或旧根不能接管。未登记或历史根继续原合同，不声称覆盖。

工具实际执行服务按可信根查冻结原O、grant/resource/delta、原持有者/generation和DISPATCHING步骤，再锁工作流核对原RUNNING责任、owner/epoch、截止时间。原元数据在工具存储数据库，不接受调用者自报epoch。换O或参数、跨实例、缺登记拒绝，不产生新效果/预算。原请求已失去责任时保存REJECTED/TOOL_STORE_NO_COMMIT；缺失或读失败依旧UNKNOWN，不推定未提交。

锁顺序scope→workflow→identity/policy→budget。工作流责任变更只有等原效果事务释放工作流锁后才能确认；已确认的责任变化先于旧写者时，原效果不会提交。预算/策略写入后、计数更新前再次检查期限；如过期，则整个效果事务rollback这些尚未提交的预算/策略写，再单独保存原意图的明确拒绝，不叫退款。原COMMITTED回放始终返回原元数据，没有新效果。查询worker的租约/epoch独立于效果提交责任，不因查询接管而获得写能力。

普通工具、非工作流根、旧混合二进制、任意外部系统不自动具有该屏障。没有自动恢复、交接到新epoch、取消/补偿或预算重置。根若已绑定即不再接受该运行之外的新意图，继续任务必须显式安排新的合法根与原预算，不能隐式接管或重放未知操作。
