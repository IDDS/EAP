# 代码完整性复核：执行观测链路

本次优先补齐会造成“业务完成但观测链路没有闭合”的缺口。检查覆盖事件 SDK、框架 Worker、Go Runner、投递接口和控制台提示；同时抽查了注册/发现、任务派发就绪检查和指标导出中的空返回及异常处理。空候选、配置不可用和有意拒绝不支持的协议不能直接认定为占位代码。

## 本轮修复

| 原缺口 | 修复后的行为 |
|---|---|
| 业务 Worker 退出后没有常驻补发入口 | 固定模板的 Go Runner 定时启动只补原日志的程序 |
| 仅靠 runtime key 无法约束尚未到达服务端的旧日志 | 捕获签名配送的原 UID/代际，封存后复核；旧日志不自动登记 |
| 重启可能重置自动重试预算 | 每个日志先持久预占轮数，再发送；最多六轮 |
| 事件已确认而报告失败时，缺少独立恢复路径 | 只补报告，保持事件及业务原回执不变 |
| 日志登记异常被吞掉 | 原回执明确返回 `backgroundDeliveryState=UNAVAILABLE` |
| 常驻补发异常不可查询 | 已认证 `/eap/state` 返回最近一轮脱敏诊断，失败不伪装为成功 |
| 发送后发生本地异常可能绕过单轮文件限额 | 按落盘后的预占轮数计入本轮额度 |
| 登记后仍可能追加事件，导致已完成状态遗漏新事件 | 封存后禁止追加；新业务必须使用新日志 |
| SQLite 初始化失败后遗留文件锁 | 初始化各阶段失败统一关闭数据库与文件描述符 |
| 生成代码移交给子 Agent 缺少 SDK 入口 | `bind_code()` 在同一 Journal/Trace 下登记消费者关联，样例执行前删除文件 |
| 页面笼统宣称没有后台补发 | 改为说明版本、原身份与预算条件，以及报告并非实时队列 |

详细行为、停止条件和状态见[后台补发契约](EXECUTION_BACKGROUND_DELIVERY.md)。本轮没有放宽现有身份、角色权限、任务幂等或 UNKNOWN 保护。

| P1 | 框架内部观测 | Kagent Go ADK 的模型/受控工具入口已接入；内部子 Agent、审批恢复和消息关系仍需显式适配 |
