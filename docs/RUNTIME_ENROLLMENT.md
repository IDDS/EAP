# 运行环境发现与复核纳管

2026-09-28。用户要求继续补齐直接在运行环境创建的实例纳管，并核查智能体创建链路。

## 接入路径

1. 进入“发现与接入 → 运行环境发现”，读取服务端配置允许的运行空间。
2. 控制接口直接列举实例。只读取空间、名称、UID、模板引用、实时状态，不读取模板环境、启动参数或凭证。
3. 选择未纳管实例，复核归属并关联目录智能体。没有身份时先在目录创建草稿。
4. 已纳管实例可查看实时状态、休眠、恢复、状态检查，动作受权限保护并记录服务端认证主体。
5. “接入验证”可为原程序签发实例凭证、验证任务握手并核对模型与调用链证据，详见 [受控接入](RUNTIME_CONNECTION.md)。原程序需要实现相应协议并通过安全配置渠道安装凭证。
6. “配置托管版本”进入同一智能体的部署页，按平台任务协议、网关和遥测要求发布新执行版本。不会改造、替换或关闭原外部程序。

API：
- GET /api/registry/runtime-inventory，VIEW_CONSOLE。
- POST /api/registry/runtime-inventory/adopt，DEPLOY_AGENTS；提交 scope/name/uid/template/agentId。
- 控制复用 /api/control/commands，OPERATE_INSTANCES；须明确 runtimeInstanceKey。

## 状态与一致性

运行纳管与业务治理分开。外部实例标记 SUBSTRATE_OBSERVED、初始内容/模型治理 UNVERIFIED，不被工作流选作可执行 Runtime。完成实例凭证与签名握手后为 TASK_READY；凭证有效、身份一致且目录 ACTIVE 时可参与任务派发。实际受管模型调用与关联轨迹到达后才显示 SCOPED_PATH；不假造心跳或正常运行。平台登记的普通记录也不直接等于内容治理覆盖，实际以网关决策与遥测证据核对。

V52 在运行登记中保存导入实例 UID 和模板引用。纳管前重新查询；同一绑定重放复用，实例键唯一约束阻止并发产生重复绑定。不同 Agent、UID 或模板冲突返回409。普通运行注册不可覆盖已导入记录，也不可转移已有实例归属。控制前再次核对 UID/模板；已消失或变化的实例显示明确状态，不继续操作。

外部纳管不开放回退、删除、试运行聊天；这些动作需要平台托管版本。读取不唤醒实例，不修改原出站策略，也不拷贝任何环境凭证。

## 范围与边界

默认发现 deployAtespace（PoC eap-agents）。额外空间由服务端 EAP_SUBSTRATE_INVENTORY_ATESPACES 配置，逗号分隔，最多合计8个；仍受底层控制接口授权。不会接受浏览器指定任意范围，也不默认跨全部租户。异步任务专用池仍由任务页及基础设施监控展示，默认不在此发现范围。管理员不应将任务控制器维护的池加入额外发现空间，当前尚无跨控制器的实例接管协议。

每空间最多5页，每页请求100项；显示截断。累计读取时间预算15秒，单次列表RPC最多5秒，前端30秒超时。部分查询失败清空该空间结果并显示不可用，不将失败当成空清单。完整清单中消失的已导入实例单独显示MISSING。

当前为访问/刷新时自动读取、人工复核归属，不是无人审批自动认领。纳管不会自动完成外部程序适配；可继续通过受控接入完成每实例凭证、任务协议验证、模型代理和OTLP链路。工具策略调用、其他模型通道与所有出站请求的治理仍需程序和网络策略适配。底层生命周期API只有名称引用，无UID原子前置条件；控制前检查能拒绝已经变化的对象，但无法保证外部并发删除重建时没有检查/执行竞态，生产接管仍需相应互斥或上游协议支持。
