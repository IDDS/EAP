# 工作流工具节点

2026-09-28：工具类型与参数保存到节点，供后续界面执行复用。当前仅开放 `calculate_sum`，不代表任意工具、MCP 或模型自主选工具。

## 界面操作

1. 在工作流画布选择已绑定智能体的任务节点，使用“常规执行”。
2. 将任务类型切换为“工具任务”，填写计算数字（逗号、中文逗号或换行分隔）。支持 1–100 个有限数字，单个绝对值不超过 10^12。
3. 点击“保存节点”。未保存或无效配置不能真实执行；刷新后仍保留工具与参数。高级配置可维护原有的上游依赖及完成后休眠选项。
4. 点击“真实执行”，在“执行过程”查看步骤和实例归属。有内容查看权限时，可主动点击“查看步骤结果”；普通运维账号只读取元数据。

编辑和执行使用统一 `runWorkflows` 能力，结果读取使用 `viewContent`。切换执行、账号或权限时清除已展示内容，不主动预取结果。

## 持久化与派发

节点配置示例（`configJson` 在节点保存接口中为 JSON 字符串）：

```json
{
  "executionBackend": "RUNTIME",
  "eapTool": {
    "name": "calculate_sum",
    "arguments": { "numbers": [10, 20, 12] }
  },
  "suspendAfterTask": true
}
```

工具必须位于绑定智能体的 AGENT / ARTIFACT 节点。保存和提交时校验工具、参数及执行方式；隔离沙箱、任意工具、额外参数字段均拒绝。其他配置字段保留。工具参数存储在工作流定义及执行快照中，属于控制台可读配置，只能填写此工具允许的数字；不是密钥存储位置。

执行器冻结所选路径及每个节点配置，仅向对应节点注入 `context.eapTool`。后续编辑不改变已入队任务；其他模型节点不会继承工具指令。新工作流执行请求不再接受全局 `context.eapTool`，返回 400 提示迁移到节点；已有相同 requestKey/objective/context 的幂等查询仍返回原运行，不重跑。直接调用参考 Runner 的任务协议仍使用 `context.eapTool`，这与工作流提交接口不同。

工具节点只能选择具备有效专属凭证、已验证接入的导入实例。恢复实例后，以专属凭证读取 `/eap/state`，要求 `tools.enabled` 为布尔 true，才发送工具任务；旧程序、禁用、重定向、无效/超限响应或读取失败均停止派发，原来休眠的实例尝试恢复休眠。该检查是参考程序能力合同，不是对任意第三方程序行为的独立证明。

成功任务响应还需包含 `tool.executed=true`、`tool.state=SUCCEEDED`、`tool.receiptConfirmed=true`。已执行但回执未确认进入 `EXECUTION_UNKNOWN`，不自动重试、不据此自动休眠。平台检查、一次性领取、实例持久记录与工具回执的详情见 [RUNTIME_TOOL_GUARD.md](RUNTIME_TOOL_GUARD.md)。
