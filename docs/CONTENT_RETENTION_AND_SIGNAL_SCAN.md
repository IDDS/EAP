# 原文保留与运营信号扫描

本轮修复系统审查 R10、R11。实施及验证状态见 `docs/evidence/retention-signals-20261019/README.md`。

## 原文到期擦除

- 新采集原文的 `expiresAt` 使用服务端接收时间加保留天数，探针 `observedAt` 只作为观测证据。保留天数允许 1–36500，默认 30。
- 历史记录的有效期限取已有 `expiresAt` 与 `createdAt + 当前保留天数` 中较早者；没有期限或探针时间偏向未来不能无限保留。调短当前期限会提前清理，调长不会延长已经冻结的较早期限。
- 默认启动 30 秒后、每批完成后间隔 60 秒处理，单批 100 条，上限 500。配置前缀 `eap.discovery.content-retention`，支持 `enabled`、`initial-delay-ms`、`interval-ms`、`batch-size`。
- 每批独立事务，逐条复用正文投影行锁，清空 `encryptedContent`、`encryptionIv`、`encryptionKeyVersion`，置 `rawRetained=false`，记录 `rawErasedAt`。重复执行不改写擦除时间。事务失败回滚，下次重新选择剩余到期记录。
- 保留原观察编号、指纹、Trace 关系、观测时间、脱敏文本及分析记录。擦除范围为在线数据库原文密文列，不代表备份、数据库物理页、binlog 或其他业务正文副本已擦除；这些需要独立保留策略。积压时到期与实际擦除之间存在处理延迟。
- 有界批次限制本轮返回和改写的记录数，不代表数据库扫描成本为常数；大表索引选择、积压收敛与锁等待仍需容量测试。

## 运营信号增量扫描

- 审批先按 `PENDING`、评估先按 `COMPLETED && !passed` 筛选，再按 ID 扫描，每类每次最多 500 条。成功/无需审批记录不占窗口。
- 两类各自持久保存游标和本轮 ID 上界。事项、事项事件、游标在原有同步锁下同一事务提交；中断后不跳过未提交记录。
- 本轮上界冻结，新插入记录进入下一轮；扫到尾部后游标归零，下一轮重新检查旧记录的状态变化，避免仅递增游标永久漏掉旧审批状态更新。
- 唯一事项键防止重复建项；相同 Trace 的较早失败不能替换较新的评估证据。未扫描到既有事项时仍核对原源状态，不能把分页缺席解释为恢复。
- `lastCompletedAt` 表示最近一次有界同步事务完成，并不表示所有积压已排空。默认每分钟同步；积压收敛速度受每类 500 条/轮及数据库负载约束。其他发现、资产和运行实例信号仍沿用原同步逻辑。

## 发布边界

V87 仅新增擦除时间、扫描游标和索引，迁移不立即删除密文、不修改业务工作流或预算。擦除由新版本定时任务执行。代码回退至旧版本不会恢复已擦除的密文，也会停止游标扫描与清理保障；不对已执行迁移做向下回滚。

本轮不核销 UNKNOWN、不释放未知预算、不重新调用历史样例，不改变权限或前端接口。
