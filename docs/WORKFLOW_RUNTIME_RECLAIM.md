# 工作流 Runtime 安全回收

自动休眠以匹配任务标识的业务终态和明确的占用证据为前提。UNKNOWN、身份不明或错误回执不能被超时推断为空闲；提交前检查、派发前复查和结束后的回收屏障共同保护任务。

## 自动休眠的提交前检查（2026-10-23）

勾选 `suspendAfterTask` 时，工作流在接受执行前检查所选路径上全部 Runtime 任务的回收条件。已有全局历史占用、同一物理 Actor 的 ACTIVE/UNKNOWN 占用、回收状态未确认或 AX 生命周期归属，都会拒绝此次提交。计划的工作流快照、执行记录和关联在同一事务中回滚，原计划仍可修改。相同请求标识的已有执行优先返回原记录，不因新的阻塞条件重新派发。

计划页通过 `GET /api/orchestration/plans/{planId}/reclaim-readiness` 读取逐步骤检查结果。接口仅查询，不创建占用、不修改计划、不清除 UNKNOWN，沿用 `VIEW_CONSOLE` 读取权限；真实执行仍要求 `RUN_WORKFLOWS`。响应包含 `planId`、整体 `allowed` 和各步骤的 `stepId/stepOrder/allowed/code/message`，不包含历史任务内容、凭据或 Actor 地址。

| code | 含义 |
| --- | --- |
| `READY` | 当前所选 Substrate Runtime 未发现回收阻塞 |
| `GLOBAL_UNRESOLVED_WORK` | 存在无法确认归属的历史占用 |
| `ACTOR_UNRESOLVED_WORK` | 同一物理 Actor 仍有 ACTIVE/UNKNOWN 占用 |
| `RECLAIM_UNCONFIRMED` | 原回收请求尚未确认 |
| `AX_LIFECYCLE_OWNER` | 所选 Runtime 地址属于 AX 生命周期管理 |
| `NO_RUNTIME` / `UNASSIGNED` | 无可用实例或步骤未分配 |
| `UNSUPPORTED_PROTOCOL` | 当前所选实例不支持此自动休眠选项，例如 HTTP Runtime |
| `AX_MANAGED` | AX 步骤使用其独立沙箱收尾流程 |

读取失败、切换计划、编辑步骤或切换账号会使旧检查结果失效。关闭自动休眠后，普通执行仍走原有权限、治理和实例准入；不会自动改变用户的休眠选择。明确的服务端拒绝与网络中断导致的提交未确认分别提示。

该检查不是资源预留，也不保证最终一定能休眠。派发前在物理 Actor 准入锁内复查，已知阻塞不会继续唤醒或调用任务；执行结束后仍使用原回收屏障处理并发新增占用。检查不替代计划其他合法性检查或业务结果验收。历史 UNKNOWN 的归属确认与处置仍需独立证据，不新增通用清除入口。

## 排队后的实例协议变化

工作流排队时冻结 `suspendAfterTask` 等任务配置，执行到各节点时会重新选择可用 Runtime。如果原实例登记改为 HTTP，或原 Actor 离线后改选 HTTP 实例，调度器在派发前再次检查协议。要求自动休眠的任务会记录当前实例绑定及明确的“未派发”原因，以 `FAILED` 结束，不调用任务、不唤醒实例，也不派发下游节点，避免悄悄跳过已承诺的回收要求。

使用原请求标识再次提交会返回原执行记录，不自动重新派发。操作者需核对实例绑定后显式另建执行。未要求自动休眠的普通任务仍按现有规则选用 HTTP Runtime；AX 任务继续使用其专属生命周期。这一检查保证本次派发遵守冻结配置，不锁定排队时的实例，也不解除历史 UNKNOWN 屏障。

## 业务结果与回收结果

`WorkflowExecutionService` 先保存步骤原始 `status/reason/httpStatus/outputSha256`，再处理 `RECLAIM` 阶段，最后结束工作流。步骤元数据新增 `reclaimStatus`，执行时间线与调度页面分别展示业务结果和资源状态：

| 状态 | 含义 |
| --- | --- |
| `CONFIRMED` | 收到原生 `SUSPENDED` 确认；是当时的状态，不保证以后不会被新任务唤醒 |
| `UNCONFIRMED` | 回收未确认；保留原失败原因，并阻止该实例的新派发 |
| `SKIPPED_BUSY` | 仍有其他执行或未知占用，未发送休眠请求 |
| `SKIPPED_UNKNOWN` | 当前占用没有明确业务终态，未发送休眠请求 |
| `SKIPPED_LEGACY` | 旧执行没有当前调度责任，未发送休眠请求 |

成功步骤无法确认回收时，工作流停止派发后续节点，步骤本身保持成功与原输出。失败步骤的回收成功/失败均不改写原业务失败原因，也不继续下游节点。

## 跨入口占用与回收屏障

`RuntimeWorkService` 用规范化的 `atespace/actor` 地址协调工作流、控制台聊天、提示词实验和团队实验，注册别名不能获得另一把锁。业务入口在唤醒/派发前持久登记 `ACTIVE`，明确终态登记 `DONE`，失联或中断登记 `UNKNOWN`。不要求自动回收的普通请求仍可并发；要求自动休眠的请求会提前检查未知占用，不会重放任务。

回收开始时锁定 Actor 行，确认当前步骤为 `DONE`、其他占用全部结束，并排除 AX 专属生命周期。随后**先提交** `RECLAIMING` 屏障，再发送原生休眠请求。新派发必须检查这道屏障。收到确认后开放新派发；超时/异常持久保留 `RECLAIM_UNKNOWN`，进程中断则保留 `RECLAIMING`。不按 TTL 清除，避免迟到的休眠 RPC 打断新任务。工作流行锁同时保护回收时的原调度责任。

旧的任务能力预检失败路径不再自行恢复休眠；预检失败不是独占空闲的证据。

## 升级与边界

V86 新建两张元数据表，并从旧工作流、聊天、实验和团队派发记录中保留未确认占用。无法解析的旧步骤、已丢失或可改写的未绑定实例关联会生成全局 `LEGACY/UNKNOWN` 阻挡，保守禁止自动回收，不修改旧回执、预算或重新执行历史任务。迁移与新版本启用之间不得存在仍可派发的旧后端；发布需要先结束旧后端，再由新后端迁移并接管。

本契约保护经这些 EAP 入口派发的业务，不承诺阻止管理员直接操作 Substrate、外部持有旧凭证的请求或不遵守终态协议的程序。AX 使用其既有专属生命周期。Runner、模型预算及取消语义未改动。

本轮没有通用的 UNKNOWN 自动核销或强制解锁接口。占用与回收屏障均不因后端重启消失；遇到回收未知需核对原实例，后续可经 EAP 创建不同名称的新实例。若历史关联缺失形成全局阻挡，应先审查历史任务，不能直接清表或按年龄释放。相同 Actor 地址即使被重建也仍受保守保护。

## 验证与限制

验证范围见[验证文档](VALIDATION.md)。历史全局UNKNOWN仍需核对原任务和实例归属；不能通过清表、按年龄释放或重放原任务绕过保护。
