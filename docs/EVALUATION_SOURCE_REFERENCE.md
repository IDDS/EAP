# 回归样本的观测引用快照

添加回归样本时，可勾选“保存时核对观测引用”。未勾选和历史样本仍为手填引用，不因系统里存在相同标识就自动变成已核对。

## 保存契约

既有 `POST /api/evaluations/datasets/{datasetKey}/items` 新增可选布尔字段 `verifySourceReference`，省略等同 `false`。沿用 `PlatformPermission.MANAGE_EVALUATIONS`，没有新增授权规则。

设为 `true` 时必须同时填写 Agent ID、Trace ID、Span ID。服务器在保存事务内：

1. 检查 Agent 存在。
2. 按 Trace/Span 查询一条已有观测记录。
3. 对规范化后的 Trace/Span 做 Java 字符串精确比较，并要求观测记录的 Agent ID 与输入相同。数据库排序规则产生的近似命中、无 Agent 归属、缺失或不一致均拒绝，样本及条数不写入。
4. 保存引用标识以及观测记录 ID、endpoint key、观测时间、核对时间。核对时间精度固定为微秒，与 `timestamp(6)` 一致。

返回值新增 `sourceReference`：

| 字段 | 含义 |
| --- | --- |
| `state` | `MANUAL_UNVERIFIED` 或 `OBSERVATION_MATCHED` |
| `observationId` | 保存时匹配的观测行 ID |
| `endpointKey` | 保存时的 endpoint key |
| `observedAt` | 该观测记录当时的观测时间 |
| `checkedAt` | 服务器完成本次核对的时间 |

未核对状态的四个元数据字段为空。V84 只新增四个可空列，不回填历史核对事实。快照列在实体中不可更新，标注不会重新核对来源。没有到可清理观测表的外键；后续观测更新或清理后，样本仍保留保存时的引用快照。

## 解释边界

`OBSERVATION_MATCHED` 只表示保存时已有观测记录与三个标识一致。现有观测入口既可能使用认证归属，也可能接收上报属性；此状态不证明上报者身份可信，也不证明输入、期望结果或实际结果来自该观测。正文仍为手填，并沿用 OFF/HASH_ONLY/REDACTED 策略；不复制观测正文或属性到快照。

界面显示“来源引用（正文手填）”及“观测引用已核对（保存时快照）”。它不是实时归属证明，也不代表模型性能改善或已发布采用。内容指纹绑定、可信源内容提取、采用→发布关联仍需后续独立契约。

## 回执和兼容

旧客户端可继续按原协议保存。新前端在勾选核对时还会验证返回的 Agent/Trace/Span、快照状态和必要元数据；旧后端忽略新字段或返回异常快照时，保留“保存结果未确认”，不自动重发。按原键查询只证明记录存在，不证明核对或正文一致。

服务端没有新增幂等提交或跨刷新恢复。前端当前页面的冻结、并发写保护、权限失效清理及人工核对流程继续有效。
