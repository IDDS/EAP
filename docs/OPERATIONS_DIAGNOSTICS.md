# 运维诊断与诊断包保留

EAP 提供统一的只读运维入口，将当前应用版本、Pod 状态、PVC 绑定和节点磁盘余量保存为可核验的诊断包。运行位置是具备现有集群读取权限的远程 Linux 运维节点，不在个人电脑安装或执行。工具不调用模型、业务工具或运行实例控制接口。

```sh
cd /path/to/EAP/deploy/delivery
python3 eapctl.py diagnose --namespace eap --output /path/to/diagnostics/check-20261025
```

输出目录必须不存在，父目录由运维人员提前准备。诊断目录权限为 `0700`，其中 `report.json` 与 `manifest.json` 为 `0600`；清单包含报告 SHA256。相同目录不能覆盖，采集中断留下的目录必须保留核对，新采集使用新目录。诊断包含内部资源名称和容量信息，应按内部运维资料保管。

## 能看到什么

| 范围 | 检查与证据 | 不能据此推断 |
| --- | --- | --- |
| 应用 | `release.json` 指定的 backend/frontend Deployment 版本、代次和副本就绪 | HTTP 内容、登录和业务成功 |
| Pod | 按 Deployment→ReplicaSet→Pod 的 controller UID 关系定位，核对实际 imageID、Ready、退出/等待原因、重启计数及删除中状态 | 同名标签的其他 Pod 可以替代目标应用；进程就绪等于任务完成 |
| 持久卷 | 指定命名空间 PVC 的绑定状态和声明容量 | 数据库可用、卷实际剩余空间或备份有效 |
| 节点 | 承载两个应用的节点 Ready/MemoryPressure/DiskPressure/PIDPressure | 运行池槽位和业务吞吐已验收 |
| 磁盘 | kubelet Summary 新鲜采样与实际 `evictionHard` 的 nodefs/imagefs 字节和 inode 余量 | 不同文件系统一定独立；整体容量、软驱逐或长稳通过 |

工具不读取 Secret 对象、应用日志、数据库正文、浏览器会话或业务参数。Deployment 和 kubelet JSON 只在内存处理，输出采用字段白名单；环境变量、命令、注解、原始错误正文、事件消息和 kubelet 其他配置不写入诊断包。验收工具另以集群实际 Secret 在内存扫描产物，不代表产品诊断命令需要 Secret 读取权限。

## 如何解释结果

- `FAIL`：观察到了版本、就绪、绑定、节点压力或磁盘阈值故障。
- `UNKNOWN`：权限不足、响应缺失、列表未完整读取、采样过期、采集期间身份/代次变化，或有效阈值未核实。
- `WARN`：观察到重启，或磁盘仍高于驱逐阈值但未达到所要求的预留空间。
- `PASS`：本次采样中所列检查通过；仍不等于生产验收通过。

汇总优先级为 `FAIL → UNKNOWN → WARN → PASS`。`diagnose` 仅在 `PASS` 时退出码为0；其他状态退出码为2，已成功写出的诊断包仍可阅读。不能因为命令返回2就删除诊断包或自动重启服务。`productionReady` 始终为false，报告列出未核实项目。

默认要求驱逐阈值以上额外预留1 GiB，可通过 `--reserve-bytes` 调整；这只是运维要求，不会改 kubelet 配置，也不是镜像构建空间保证。默认允许采样最多120秒，通过 `--max-sample-age` 调整；未来超过30秒的采样同样拒绝。缺少阈值不套用默认值，`containerfs` 不猜测别名和继承关系，列为未核实。空间充足也不会掩盖 inode 耗尽。

命名空间列表单次最多200项，不自动追随继续游标；超限或不完整时报告未核实，不把返回的部分资源当作完整集群。仅检查当前应用 Pod 所在的最多16个节点。权限不足时保留其他可用部分，不自动创建 RBAC 或扩大 EAP 应用身份权限。Summary/configz 权限应由运维系统另行管理。

各接口不是事务快照；工具复查命名空间 UID 和应用 UID/代次，但不能证明采集期间没有其他状态变化。报告保存采样时间，只用于本次排障，不作为长期容量承诺。

Kubernetes 的文件系统信号、硬驱逐阈值及 `containerfs` 限制依据[官方节点压力驱逐文档](https://kubernetes.io/docs/concepts/scheduling-eviction/node-pressure-eviction/)（访问日期：2026-10-25）。本工具仍以实际节点数据为准，不根据文档默认值补齐缺失证据。

## 保留计划

```sh
python3 eapctl.py plan-diagnostic-retention --root /path/to/diagnostics --days 14 --keep 3
```

工具只检查根目录下的直接子目录。有效诊断包必须恰好包含两个普通文件、合同匹配且报告摘要一致；单文件不超过1 MiB。符号链接、额外文件、残缺或篡改的包、未来时间和非诊断目录均计入不受管理项，不能成为清理候选。目录超过1000项时停止，不输出部分清理计划。

按报告记录时间判断年龄，不用可被复制或touch改变的文件修改时间；每个命名空间保留最新N份，再列出超过保留天数的剩余候选。每个候选包含两个文件摘要及字节数。**只生成计划，不执行删除**；人工操作前必须重新核对摘要。此功能不清理业务记录、原始验收证据、SQLite Journal、数据库物理页、binlog或备份，不代表业务数据保留主线已完成。

## 验证范围

远程交付工具最终61项测试通过，覆盖故障/权限缺失/列表截断、真实所有者关系、镜像不匹配、时效、字节及inode门槛、未知阈值、诊断包权限/防覆盖及保留计划保护。现有集群只读验收21项通过、0故障、2项containerfs阈值未核实，报告如实返回UNKNOWN；未重建或重启应用，未改变旧业务、预算和执行记录。详见[验证范围](VALIDATION.md)。
