# 进程退出检测与安全容量回收

## 当前状态（2026-10-02）

底层退出检测已从独立池灰度扩展到两个默认运行池：API两副本、两节点组件、普通池2个/隔离池1个工作进程均已升级并核对实际镜像。旧失败v4准备任务按用户确认经原生接口清理，失败发布历史/v5保留。三个既有快照跨两节点兼容恢复、只读状态/回执及四角色接口通过，最终休眠。

具体迁移证据和剩余边界见 [默认运行池迁移](RUNTIME_DEFAULT_POOL_ROLLOUT.md)。其他命名空间/历史缩容池未全量升级。本页下方测试表是10/1退出检测灰度结果，本轮未重复故障注入，不等于生产验收。

## 为什么需要底层观测

此前合成进程退出后，runsc 中 agent 已 stopped，但基础设施容器 _pause 仍运行，控制元数据和 EAP 仍显示 RUNNING。业务 HTTP 502 和监控 CONNECTED 均不能证明进程健康。EAP 的 RUN_HEALTH_CHECK 读取控制元数据，ACKED 只代表命令成功完成。

新链路只读实际运行时状态，不访问会唤醒实例的 HTTP 路由：

1. 控制面取得与原生暂停、恢复、回退相同的 actor 租约，重新读取实例 UID 和当前分配。
2. 节点组件按 worker Pod UID 转发内部健康 RPC；工作进程核对 active actor UID、激活会话绑定的 runsc 和应用容器名单。
3. 所有必需应用容器的状态都明确，且至少一个 stopped，才确认退出。_pause 不充当应用；缺失、重复身份、未知状态、超时、旧版本不支持、生命周期切换均保留当前状态和额度。
4. 先持久化 CRASHED，并保留 workerAssignment，表示清理尚待确认；终止沙箱和外部卷分离确认后才释放槽位和清空分配。
5. 清理失败或回执丢失保留占用；下一轮或服务重启后继续清理。不会自动重试业务、自动回退快照或重新调用模型。

快照恢复仍由 EAP 的显式 REVERT → RESUME 完成。故障后未保存的内存变化不会进入先前快照。该机制不为任意外部工具副作用提供 exactly-once 保证。

## 性能与配置

默认关闭，显式开启 `--actor-health-atespaces=eap-agents,eap-ax`。`--actor-health-interval=15s` 表示完成一轮扫描后的等待间隔，不是故障检测 SLO；最小配置 5 秒。每个 API 副本 4 个处理者、队列 32、分页 100；单个协调操作最多 45 秒，健康 RPC 最多 3 秒，实际容器状态读取最多 2 秒，生命周期锁等待最多 20 毫秒。子进程标准输出限制为 1 MiB，已回归验证不能经 ReaderFrom 绕过限制。

调度/确认路径采用确定性操作，不引入 LLM。这里借鉴联通研究的实际资源释放确认和有界控制路径；没有实现研究中的 LLM 调度、内核调度或完整联合优化算法。大规模扫描、长期压力和生产 SLO 尚未验证。

## 验证结果

所有编译、生成、测试、镜像和浏览器均在远程 PoC 运行。

| 范围 | 结果 |
| --- | --- |
| ateom-gvisor + atelet | 140 个顶层用例通过，含子用例 399；3 个既有 root 文件权限模拟跳过 |
| controlapi + ateapi | 220 个顶层用例通过，含子用例 1261；0 失败、0 跳过 |
| 输出限额回归 | 修复前复现绕过；修复后通过 |
| 固定源码基线应用校验 | git apply --check 通过 |
| 正常恢复/休眠 | 3 轮通过，无误报 |
| 实际 process.exit(41) | 一次注入；观测 CRASHED 8389.8ms，清理后分配清空 8479.9ms |
| 槽位复用 | 第二实例在同一单槽位池恢复，owner=null、counter=0，无状态串扰 |
| 显式快照恢复 | 恢复计数 6，未保存的 10000 增量被丢弃 |

8389.8ms/8479.9ms 是一次合成故障的观测耗时，包含 150ms 延后退出及轮询开销，不是平均值、P95 或生产承诺。回执丢失、未知探测、租约/身份防陈旧和重启后继续清理已做代码级测试；没有做真实断网/断电、外部卷故障或控制服务在清理中途强制重启。未运行 -race。
