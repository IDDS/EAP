## 进程退出缺口

应用按测试请求执行 `process.exit(41)`，gVisor 应用容器已停止，pause 容器仍运行。等待窗口内控制 API 没有自动转入 CRASHED；随后只读诊断仍见 RUNNING。EAP 的 RUN_HEALTH_CHECK 实际读取控制元数据，故返回 ACKED / RUNNING；这表示查询完成，不能作为业务进程健康证据。

现有运行时源码中，控制 RPC 的带崩溃标记错误和 worker 丢失有状态转移路径；本次应用自行退出未触发该路径。没有修改底层运行时，没有把一次 HTTP 失败强制映射成 CRASHED，也没有覆盖已有快照。原失败记录与进程状态保留。

下一项应补底层进程退出事件或无唤醒健康观测，并向控制面可靠上报。必须带实例 UID、worker 身份和分配代次，处理主动休眠/回退、旧事件、新分配、多副本和重启；幂等释放槽位且只记一次崩溃，保留最后有效快照。未知业务执行不能自动换键重试。
