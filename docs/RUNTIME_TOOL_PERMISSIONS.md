# 工具权限、共享额度与研究落地

## 当前合同

工具通道必须同时满足实例专属凭证有效、显式工具授权、行为检查、数据治理和一次性领取。V55 不自动为历史智能体授予工具权限；尚未配置时拒绝新工具检查。已经领取的历史许可不受新策略撤回影响，历史回执仍可以提交。

入口：智能体目录 → 运行环境 → 已纳管实例 → 接入验证 → 工具权限与额度。页面主要使用业务名称，不要求操作人员理解底层产品名。

- 所有 `viewConsole` 用户可以读取授权状态、版本、允许的工具和使用量。
- `governance` 能力可以配置授权；由现有 `PlatformPermission.GOVERNANCE` 统一决定接口和界面能力。运维角色拥有实例凭证操作能力，不因此拥有扩大工具授权的能力。
- 工具名称区分大小写，名称与 TOOL/MCP 类型必须同时精确匹配；每个智能体最多 64 项。没有通配符，也没有资源路径、参数级或委托链级授权。
- 同一 agentId 的所有外部接入实例共享累计领取上限，最高 10 亿。额度在成功领取时消耗，检查阶段不预留。检查通过也不保证之后能领取。
- 每次授权保存增加版本。尚未领取的旧版本检查会在领取时被拒绝；客户端不可把这一行为当作自动重试业务副作用的许可。
- 保存使用 `expectedRevision` 防止覆盖别人修改；配置变更记录审计操作者与前后授权元数据。写接口不能设置已领取次数。
- 领取持有实例连接锁，再持有智能体和授权行锁。同一事务增加共享用量、标记 CLAIMED、保存工具观测；并发实例不会分别消耗超过同一累计上限。配置初次创建同样以智能体行锁串行化。
- 失败回执、未知结果、响应丢失、凭证换发、休眠恢复和新实例都不会清零或返还额度。可信治理人员可以增加累计上限，但不能把上限降到已用量以下。
- 停用只能阻止后续领取，无法收回已经领取且可能正在执行的外部操作。没有接入客户端的工具调用仍不受本通道控制；不是内核级或网络级全量强制拦截。
- 工具参数和输出仍不写入授权或检查表，只保存归属、决策、摘要与回执元数据。授权范围拒绝发生在行为/数据分类之前，避免不必要的内容检查和附属记录写入。

## API

`GET /api/registry/runtime-tools/policy?instanceKey=...` 返回该实例所属智能体的共享授权。未配置返回 revision=0、enabled=false、空列表与零额度。

`PUT /api/registry/runtime-tools/policy`：

```json
{"instanceKey":"eap-agents/example","expectedRevision":0,"enabled":true,"allowedTools":[{"name":"calculate_sum","kind":"TOOL"}],"claimLimit":100}
```

读取返回 `agentId / revision / enabled / allowedTools / claimLimit / claimedCount / remainingClaims / updatedAt`。检查记录追加 `policyRevision`，历史记录为 null。新原因码：`TOOL_POLICY_MISSING / TOOL_POLICY_DISABLED / TOOL_SCOPE_DENIED / TOOL_POLICY_CHANGED / TOOL_BUDGET_EXHAUSTED`；均为 BLOCKED，不能领取。前置拒绝的行为/数据结果为 `NOT_EVALUATED`，不伪装为完成了内容审查。

V55 为附加表与可空字段迁移。旧后端不识别新的工具授权约束，回退到旧后端会使这些约束失效；不能在仍开放工具通道时盲目回退。

## 研究借鉴与边界

依据仓库内部两份研究材料，而不是把研究目标当成已交付产品：

- [字节权限与安全研究](../BP/EAP融资BP_精品版_20260929/research/sources/bytedance_security.md)：版本校验、共享持久额度、未知副作用保留用量、恢复后读取当前授权。本轮只落地工具通道的领取额度；未实现完整委托授权路径、权限证明或效果提交方强撤销。
- [联通多层协同调度研究](../BP/EAP融资BP_精品版_20260929/research/sources/unicom_runtime.md)：提交前复核、共享资源记账和实际释放确认。授权热路径使用确定性事务，不引入 LLM 调度等待。进程退出确认后再清理并释放运行槽位已完成底层灰度验证，默认工作池尚未升级；见 [退出检测合同](RUNTIME_PROCESS_EXIT_HEALTH.md)。不能用控制状态 RUNNING 或指标 CONNECTED 代替进程存活证据。

性能优化需要分别测量启动/恢复延迟、槽位占用、检查/领取延迟和 CPU/内存。合成检查的对照计时不代表生产容量或推理性能提升；本轮不宣称已实现研究中的 LLM 调度、内核调度或归因算法。

## 验证

远程回归：默认未授权红测先复现 APPROVED 缺口；修复后后端全量 354/354、前端 156/156 与类型/构建通过。覆盖跨实例竞争额度、版本撤销、凭证换发、未知/失败不返还、并发配置、权限一致及页面身份/请求竞态。首次后端全量暴露 JSON 数据类型映射错误，改用 Hibernate JSON 类型后重跑通过，保留失败记录。

真实 Agent39 两个实例共享额度，8 并发只成功领取 2 次、其余 6 次阻断；未知/失败保留预算，凭证换发和快照恢复不清零。增加累计上限后真实实例内求和得到 42，最终累计领取 3、模型调用 0。测试授权已停用（revision=8），两实例凭证已撤销，实例已休眠。

四角色 API 与真实浏览器通过：viewer/operator 只读，governance/admin 可编辑；治理界面实际保存 1 次。最终撤销状态四角色及 390px 布局复验通过，页面/API 异常和业务写入均 0。合成 25 次/路径：范围前置拒绝中位30.62ms/P95 37.06ms，完整允许检查47.39ms/59.74ms；这不是前后版本速度对照。证据在 K8Substrate artifacts/eap-tool-policy-20260930/，原始归档 SHA256=202c1f6713fd850dc27d5608e5b7608b768d3bb21522115ebc0e1a48ee95065a。
