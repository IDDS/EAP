# 启动就绪探测：性能与访问边界

## 当前结果（2026-10-02）

底层补丁已通过远程相关包和独立工作池验收；现已按用户确认清理旧v4，并升级两节点组件和两个默认工作池。旧快照兼容与权限结果见 [默认池迁移](RUNTIME_DEFAULT_POOL_ROLLOUT.md)。下方190/503测试与753→16实验为10/1结果，本轮未重复；EAP前后端未改未重测。

旧实现固定每1毫秒探测一次。实际历史模板eap-a7-v4的/路径在3000端口持续404，单次120秒就绪窗口约4.7万次请求；EAP早已将v4发布标记FAILED，底层模板准备仍反复重试，长期占用一个槽位。v5已READY；v4仅被自己的准备任务引用，没有业务实例或快照。探测压力修复与旧失败任务清理现均已完成；一般EAP发布失败的自动取消链路仍需另行产品化。

## 新行为

- 首次请求立即执行；失败后等待从1ms翻倍至100ms。快速就绪仍立即通过，持续失败不再维持1ms高频轮询。100ms为最大计划等待，实际响应时间还受网络和调度影响。
- 只接受配置地址直接返回200。301/302等重定向按未就绪处理，不访问其目标，避免被工作负载引导访问其他地址或把其他页面的200当作就绪。
- 总就绪超时作为请求上下文，覆盖进行中的HTTP请求和等待。超时后的200不能变成成功；外部取消保持取消语义，不伪装为工作负载故障。
- 最多读取4KiB响应体，然后关闭。短响应仍可复用连接；不会为了复用连接无限读完整响应。
- 不改变就绪失败后的原生重试/故障语义，不自动终止任意慢启动任务、不自动执行或重放业务。EAP状态检查仍以控制元数据为准。

这是确定性热路径改进，借鉴有界资源消耗及目标范围约束；不是LLM/内核调度，也不是完整委托权限实现。旧版行为会跟随重定向，本次有意收紧为直接200，使用重定向的探测配置需改为真实就绪地址。
