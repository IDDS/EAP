# 固定 HTTP 夹具的构建期字节码缓存

2026-10-22。**缓存缺口已验证并补齐；启动超时尚未解决。** 构建工具在固定镜像的解释器中生成缓存覆盖层，不改变 Runtime 源码、解释器、入口、权限或 20 秒任务截止。候选镜像只用于新的专用验收实例，没有更新默认原生/Kagent Runner。

## 检查发现与修改

新批次使用 CPython 3.12.15。普通容器中以 `-B` 禁止导入过程写缓存，以免第一次测量改变第二次测量的文件状态。固定导入目标为 `http_actor_probe` 和 `http_actor_server`，不调用 main、HTTP、模型或真实凭据。计数包装在 finally 中恢复，只输出聚合次数/字节/耗时，不输出凭据、环境或业务内容。

| 镜像检查 | 观察器 | 服务 |
| --- | ---: | ---: |
| 原镜像源码读取/运行期编译 | 6 | 4 |
| 原镜像字节码读取 | 62 | 66 |
| 原镜像文件状态查询 | 409 | 426 |
| 原镜像编译 CPU 耗时 | 约26.6ms | 约28.0ms |
| 候选镜像源码读取/缺失缓存读取/运行期编译 | 0/0/0 | 0/0/0 |

已有缓存覆盖大部分导入，补齐缓存只处理其中一项开销；文件状态查询、读取和非 CPU 等待仍需调查。计数来自普通容器的受控探针，**没有测得 gVisor 中的实际缓存命中次数**，不能把探针的零编译直接标为 gVisor 零编译。

新增[构建工具](../deploy/substrate-poc/prepare_http_bytecode.py)和[7项回归](../deploy/substrate-poc/test_prepare_http_bytecode.py)：

- 仅在匹配镜像的 CPython 3.12 与 `-B` 下运行，固定导入两个入口以收集依赖；不执行入口 main。
- 对收集到的源码检查既有缓存，只为缺失或失效项生成覆盖文件。限定 `/opt/eap-mcp`、`/usr/local/lib/python3.12`，拒绝越界、符号链接、相对路径和第三方包目录。
- 写入独立输出目录，保留源码和既有缓存；生成后核对源码摘要/mtime及缓存头。
- 显式使用 `TIMESTAMP` 与 `optimize=0`，保留常规源码校验和 assert；不启用无校验 hash 或 `-O`。
- 输出解释器版本、magic、源码/缓存摘要，构建镜像时只 COPY 缓存层；发布前验证所有继承层、入口配置和新增文件集合。

本次扫描97个带源码路径的已加载模块，77个缓存保持，生成20个缓存文件。其中包含启动模块/frozen模块对应的源码文件，20不是原来运行期编译次数之和，也不意味着全部会被两个实际脚本入口读取。直接以 `.py` 执行的入口本身仍由解释器解析，不能宣称脚本解析已全部消失。

这些校验方式依据 [Python 3.12 py_compile 文档](https://docs.python.org/3.12/library/py_compile.html)及 [`-B` 文档](https://docs.python.org/3.12/using/cmdline.html#cmdoption-B)，访问日期2026-10-22。TIMESTAMP按时间戳和文件大小失效，不是内容签名；镜像内源码及缓存的完整性另外通过固定镜像摘要和构建清单核对。
