# 企业落地四道关：交付与验收清单

本清单把企业反馈转化为 EAP 的场景交付条件。它是后续建设与验收的工作依据，不代表任一场景已经通过，也不替代目标企业对权限、数据和业务结果的确认。先选定具体业务、责任人及系统，再逐条记录证据；未验证项保持未验证。

## 腾讯平台能力布局的参考

用户提供的腾讯平台发布会图片展示了四项能力升级：开放平台（腾讯生态、企业自有系统）、企业级安全解决方案（可管、可控）、可观测中心（可观测、可评估）、WMA 托管智能体服务（规模化分发、场景化部署）；底层同时提出 Agent Runtime 升级及成本、性能目标。这里仅依据图片中的表述整理，不推断其具体产品实现、集成范围、实际成本或验证效果。

| 图片中的能力方向 | 对应企业需求 | EAP 的建设重点与当前边界 |
|---|---|---|
| 开放平台 | 跑得通 | 打通授权数据、业务接口和任务结果；现有运行时、工具与连接器是基础，具体业务系统仍需单独适配和验证。 |
| 企业级安全 | 可托付 | 围绕身份、权限、数据流、审批和审计验证端到端边界；已有治理能力不能推断覆盖全部外部路径。 |
| 可观测与评估 | 可衡量、可运营 | 关联任务、模型、工具、成本与业务结果；模型用量或执行成功不等于业务收益。 |
| 托管智能体服务 | 好落地 | 形成可部署、可管理、可复制的场景交付流程；现有计划复制不代表跨团队和跨环境全自动迁移。 |
| Agent Runtime、成本与性能 | 四关的共同运行基础 | 验证执行可靠性、隔离、资源使用及恢复能力；成本和性能需要在明确负载与基线下测量，不能照搬图片中的目标。 |

可持续进化需要把业务反馈、评估、版本变更和运行证据连接起来，观察改进是否有效；图片中的能力名称本身不证明闭环或收益已经实现。

用户后续提供的现场图片还强调“靠谱”（高质量交付结果）与“安全”（不越界、不失控），并将可信 AI 治理归纳为行为可控、过程可溯、数据可管。对 EAP 而言，这意味着要把结果质量验证和安全边界贯穿真实任务全流程：明确允许的操作与审批、可追溯的执行与证据链、数据访问和流转范围，再以业务结果验证是否可靠。这里仅整理图片中的方向，不推断腾讯具体能力或实施效果。

## 1. 跑得通：从业务输入到可核对的结果

对一个具体任务，明确触发入口、输入数据、业务系统及接口、执行身份、工具和模型、结果去向与业务负责人。先在受控环境验证最小任务，再按业务授权扩大范围。

验收至少包含：

- 能在授权范围读取所需数据，并记录数据来源、时间和范围；不可访问或数据缺失时明确提示。
- 能通过 EAP 发起和追踪任务，关联步骤、调用、结果与原业务对象；业务结果由业务系统或责任人核对，不能仅凭模型输出判定成功。
- 如涉及外部写入，先确认目标接口的授权、幂等范围和期限、关联字段及原结果查询方式；响应丢失、超时、查询权限不足和结果不唯一时保留未确认状态，指定查证责任人。
- 对失败和未知结果保留原操作标识及证据；只读查证与重新发送写请求分开，未经明确授权不自动重放。

现有工作流、运行时和工具保护可作为基础；受控计数工具的存储保证不自动适用于外部工单或其他业务接口，目标系统的原操作查询和幂等合同须单独核验。最新真实三智能体案例未完整成功，不作为此项通过证据。

## 2. 可托付：身份、数据和操作边界可核验

针对同一个场景，列明操作者、Agent、运行实例和业务接口的身份与权限，确定数据分类、允许的模型与工具、审批规则和审计责任。

验收至少包含：

- 使用实际角色和运行身份验证允许与拒绝；前端按钮能力和服务端拦截均遵循 `PlatformPermission`，业务系统仍须独立验证自身授权。
- 验证敏感数据在输入、调用、输出与留存各环节的处理方式和可见范围；记录数据出口、保存期限和责任人。
- 对高风险操作验证拦截、审批、撤销及异常状态，并核对审计记录；审批通过不能替代业务系统对执行身份的授权。
- 针对目标部署验证项目隔离、网络、TLS、身份管理、备份恢复和可用性；测试未覆盖的部分不得标记为生产就绪。

已有治理网关、权限与审计能力是基础，不代表任意系统或网络路径已纳入治理。身份与生产部署条件以目标环境的实际验证为准。

## 3. 可衡量：成本、效果和收益有依据

在试点开始前，与业务负责人约定任务定义、统计周期、人工处理基线、结果确认规则、币种与成本范围。结果至少区分执行成功、业务确认有效、未解决和未知，不能把调用量或模型成功响应直接算作收益。

验收至少包含：

- 每次任务尽可能关联执行记录、模型用量、业务结果和来源记录；关联缺失时显示未归因，不能按猜测分摊。
- 分别报告任务数、业务确认有效数、人工介入及耗时、已采集成本和数据覆盖率；标明人工、模型、工具、基础设施等哪些成本已计入、哪些未计入。
- 人工节省时间应说明基线、样本和测量方法；换算为金额的假设与业务确认分开展示，不把估算直接称为已实现收益。
- 可计算时，ROI =（同一周期、同一币种的业务确认收益 − 纳入统计的成本）÷ 纳入统计的成本；成本为零、缺失或币种不可比时不计算，说明原因。

现有业务价值事件、来源记录关联及用量能力可作为基础；实际客户效果、完整成本和收益仍需接入与确认。混合币种不可直接相加。[项目记忆](PROJECT_MEMORY.md)记录了价值事件及混币处理的既有范围。

确认边界：当前价值事件的确认人字段由调用方填写，连接器也可以配置固定确认主体并自动导入；系统不会独立验证该主体是否实际审核过每条结果。汇总字段名称中的 `validated` 是现有接口命名，不是经独立审核的证明。收益、改进率及模型口径投入产出比都应结合来源、人工确认和未计成本核实，不能仅因出现价值事件就作为已实现收益。

2026-11-02 PoC 已部署：管理页的任务关联和价值趋势使用筛选后最多 100 条价值事件，并展示符合条件的总数及取回数量；趋势图最多显示其中 16 条，图内累计从第一条展示记录开始。这些图表是有限样本，不应与汇总窗口的全量价值直接等同。页面和连接器的来源线索不证明已核实业务结果；主要统计读取失败时，页面隐藏旧统计并提示刷新。

实现边界：当前汇总主要使用已采集模型费用，不能直接当作覆盖人工、基础设施等全部投入的企业 ROI。PoC 已部署的费用来源标记将新增记录区分为调用方提供、网关估算和未提供，旧记录及旧版本写入保持未知；调用方提供不代表已核对账单，网关估算也不代表供应商收费。覆盖统计按所选时间窗口内全部币种计算，金额仍按所选币种计算。零成本 ROI 不再给出确定数值；真实企业全成本和收益归因仍待接入验证。

2026-11-01 PoC 已部署：当已记录模型事件含网关估算、未提供或历史未知的费用时，不计算汇总的模型口径净收益和投入产出比；单个主体按其整个窗口的事件分别判断。原因是现有估算可能在缺少价格配置时为零，无法据此确认费用完整。费用来源判定覆盖全部币种，金额仍按所选币种统计，因此会保守地隐藏部分原本可能可算的结果；已采集金额和业务确认价值仍可查看。调用方提供的金额也不等于账单已核对，事件齐全不代表企业全成本齐全。

2026-11-03 本地候选（尚未部署）：所选币种没有模型调用记录时，汇总不计算模型口径净收益和投入产出比；单个主体没有所选币种调用记录时，该主体也不计算。明确上报零费用的调用仍可计入已记录费用，分母为零时不计算投入产出比。此条件只排除没有任何记录的情况，不证明已记录事件覆盖所有调用，也不构成企业完整成本或业务收益核实。

同日后续候选进一步要求：每个登记价值的归属主体（包括共同贡献中的各主体）在所选币种至少有一条模型调用记录，才显示汇总模型口径净收益和投入产出比；不影响记录充分且费用来源符合条件的其他主体的单独计算。该检查只是最低观测条件，不证明调用与价值逐笔对应，也不证明全部费用、真实收益或完整 ROI 已核实。

同日新增价值金额来源候选（尚未部署，包含数据库 V98）：新写入区分金额已提供和未提供，旧数据及旧版本写入的来源保持未知；历史数字不回填或改写。无价值记录、所选币种任何价值金额未提供或来源未知时，不计算汇总净收益及 ROI；单个主体按其自身价值记录判断。已明确填写零金额与未填写不同，仍需独立核实业务事实。页面显示来源覆盖和未提供状态；兼容用的存储零值不等于实际价值为零。升级期间旧版本仍可能按旧规则计算，发布前须制定兼容、切换和回滚方案；新字段不证明价值真实性或成本、价值逐笔关联。

新版页面若连接不返回价值金额来源统计的旧服务，会隐藏汇总和各主体的净收益及 ROI；这项界面保护不约束直接调用旧后端的 API 客户端。

## 4. 好落地：可复制、可运营、可改进

首个团队通过前三关后，选第二个团队或独立环境验证复制。列出场景配置、依赖、权限申请、责任人、运行手册和评估标准，并分别处理环境特定参数与凭据；凭据不进入模板或交付文档。

验收至少包含：

- 第二团队按交付材料完成接入、授权、运行和业务验收；记录耗时、人工操作、失败及差异，不能仅凭计划复制功能认定跨团队复制成功。
- 指定业务、平台、安全与运行责任人，明确告警、异常查证、升级和停用流程；验证操作人员能找到任务、原结果和相关证据。
- 建立固定周期的质量、成本和安全复盘；选择有代表性的样本及业务评价标准，比较变更前后效果并保留版本与决策依据。
- 对未确认、覆盖不足或未验证的事项明确责任与后续动作，不把没有记录解释为没有问题。

现有未提交计划可复制，但会清空执行历史及成员分配，不能由此推断连接器、身份、权限或环境已自动迁移。参见[项目说明](../README.md)。

| 场景与责任人 | 业务目标、任务边界、业务/平台/安全负责人 |
| 系统与权限 | 数据来源、目标接口和版本、身份、授权范围、环境 |
| 跑得通 | 测试任务、原操作标识、业务结果与证据，失败/未知记录 |
