# 逻辑 Agent 执行观测控制台

入口为“运行与观测 → 执行关系”。本视图使用执行事件、关系与投递报告查询接口，独立于模型统计窗口、端点与 Trace 筛选；不新增执行、重放、回收或授权动作。后端契约见 [执行事件 v1](AGENT_EXECUTION_EVENT_CONTRACT.md)，框架范围见 [支持表](FRAMEWORK_SUPPORT.md)。

## 阅读顺序

1. 按智能体编号或完整事件流编号查询。每页最多读取 100 条事件，按服务端接收记录编号向后分页。
2. 从当前事件页涉及的流中选择一项。事件流绑定运行实例、身份代际与生产者；同一流可能跨多个事件页，页面计数不是全流事件总数。
3. 在父子列表中选择一次逻辑 Agent 执行，查看其独立执行编号、父执行、工具调用及相关代码摘要。相同定义的重复执行不会合并。
4. 对照结构缺口与报告状态定位问题。代码摘要不能恢复源码；需要进一步检查业务效果时，转到工具关联的 Trace 或原任务记录。

关系查询返回的是该流的已接收事件派生结果，不是当前事件页的局部推断。Agent 与工具列表各按 50 项分组呈现，深层父子关系采用迭代遍历，缩进有界、完整编号可见。摘要仅展示所选执行及工具引用的产物，最多显示前 50 条并明确截断。

## 状态与可靠性

- “报告成功/失败/取消”表示认证生产者的报告，不是内核或外部工具对效果的独立证明。
- “记录未齐”可能缺少开始或结束事件，不能据此断言仍在运行或从未执行。
- “顺序矛盾”与缺失父节点、序号、工具及产物等缺口分别显示。
- “已收到事件无结构缺口”不等于业务成功，也不能排除尚未交付的尾部事件。没有记录时明确提示接入 SDK/适配器，不生成模拟执行。
- 网络/接口错误显示错误与重试入口，清除旧结果，不作为空记录或零值指标显示。

查询状态由独立 composable 管理。筛选变化、刷新、账号切换、权限撤销与组件卸载都会中止旧请求并清空结果；即使底层请求忽略取消，版本与会话核验也阻止迟到结果回填。所有读取遵循 `/me` 的 `viewConsole` 能力，不解析 JWT 或自行使用角色名授权。

## 投递状态

同一筛选下显示最近一次认证客户端报告，每页最多50条，独立刷新和翻页。四个计数分别为报告总数、客户端已确认、客户端待确认、服务端已接收。点击“查看已收事件”打开原事件流；服务端无事件时按钮禁用。

报告接收时间、序号、累计投递尝试和查询时间同时保留。查询时超过5分钟的报告会标为旧快照。凭据状态来自当前保存的身份元数据，不进行在线探测；已撤销、换代、过期或离线分别提示。身份变化后保留历史报告，不续期、唤醒或重新派发任务。

没有报告明确显示“未知”，不填零；读取失败独立显示错误。服务端已接收但客户端待确认可能是回执丢失，不应重跑业务。界面没有后台补发或任务取消按钮，协议与处理边界见[投递状态](EXECUTION_DELIVERY_STATUS.md)。

## 实现和设计

`AgentExecutionExplorer` 负责筛选、事件分页和流选择；`AgentExecutionGraph` 负责流内父子、工具与摘要阅读；`ExecutionDeliveryPanel` 独立读取同筛选下的投递报告；`useExecutionQuery` 负责查询生命周期；纯函数负责分组和有界树遍历。普通遥测加载失败不会阻止执行关系组件独立读取。

沿用 EAP 的界面色彩：主文字 `#193246`、次文字 `#52697b`、操作色 `#087f9a`、分隔线 `#d7e2e9`、画布 `#f4f6f8`、内容区 `#ffffff`。字体继承全局控制台样式，只有编号与摘要使用等宽排版。桌面采用“父子列表 / 执行详情”两栏，窄屏改为上下排列；按钮保留键盘焦点和选中语义，状态用文字表达，不只依赖颜色。

界面不扩展跨流/跨实例关系，不自动捕获框架内部执行，也不补算缺失时间。2026-10-24 控制台修正版部署时，远程前端 531 项、类型/构建及四角色两种宽度的 8 个浏览器场景通过；当时生产事件表为空，非空关系使用浏览器夹具。见[界面发布记录](VALIDATION.md)。

同日后续真实框架验收中，EAP 创建 LangGraph 与 AutoGen 两个样例 Agent，并通过工作流调度固定求和任务，实际写入 18 条事件。该历史样例可按各自 Agent 查询 3 次同进程逻辑执行、1 次工具和代码摘要。四角色 × 桌面/手机 × 两框架，共 16 个浏览器场景通过，全程读取真实 API，无图夹具。任务完成后两个实例已显式休眠、凭证已撤销，历史关系仍可读取。该轮保持前后端镜像与 Schema91，不表示已经支持通用框架创建。[真实工作负载证据](VALIDATION.md)、[验证范围](VALIDATION.md)。

## 跨实例关联

事件流详情显示 `DELEGATE` 与 `CODE_HANDOFF`，区分来源声明待确认和双方已确认。双方确认后可跳转另一实例的执行流；关联不授予执行权限，不会改写原父子关系。协议、SDK 接入与独立样例见[跨实例执行关联](EXECUTION_LINKS.md)。
