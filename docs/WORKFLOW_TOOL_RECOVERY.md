# 受控工具步骤的持久查询责任

协议 `workflow-tool-query-v1` 只覆盖 `controlled_counter_increment / poc-counter-v1`。调度、Agent 性能调优、权限治理仍是主线；这次完成的是查询责任和核验事实的持久化，不代表通用恢复完成。

## 从派发到核验

1. 新工作流保存 `recovery_version=1`。执行者领取原运行的 `owner_id / owner_epoch`，进度写入同时核对版本、所有者和 RUNNING 状态。
2. 受控工具派发前，保存原 DISPATCHING 步骤，核对冻结节点中的类型化参数，登记持久查询任务。登记绑定原运行、节点、taskKey、根、grant、O、对象、增量，以及原实例 UID、身份 generation、策略和工具合同版本、参数指纹。已有工具意图不能冒充新运行；已有查询任务只接受同一原绑定。
3. 外部请求仍按原 taskKey 和 O 执行一次。查询队列没有执行、续授权、预算领取、退款、取消、补偿或派发下一节点的入口。
4. 独立查询 worker 每轮最多领取 8 个到期任务，不占用长工作流执行线程。每次查询有新的查询轮次和 30 秒责任租约；这不是新的业务 O。未完成租约到期后可由另一个查询者接管。
5. 查询只读取原工具存储，按原根、O、grant、持有者、generation 和参数指纹核对。结果与责任通过原查询所有者、轮次和有效租约条件写回，过期查询者不能覆盖较新事实。

同一数据库先保存派发意图和查询责任，再发外部请求。二者之间若中断，不认为工具未执行；责任缺失也不能推导外部无效果。已登记任务持续保存查询责任。

## 事实与责任

| 状态 | 依据 | 后续行为 |
|---|---|---|
| PENDING / CHECKING | 已登记原绑定，等待或正在读取 | 保留查询责任 |
| UNKNOWN | 缺失、PREPARED、读失败或指纹不匹配 | 按原绑定继续查询，不重试执行、不退款 |
| CONFIRMED | 原存储 COMMITTED，独立 effectId / 计数及 TOOL_STORE_VERIFIED | 固定原事实，不再自动查询；不推进工作流 |
| NO_COMMIT | 原存储 REJECTED / TOOL_STORE_NO_COMMIT | 保存明确拒绝事实，不退款、不创建新意图 |

核验保存原效果的元数据，不把运行程序自报、MCP 名称、取消 ACK、授权撤销或实例休眠作为效果证明。撤销后仍能读取原事实，不能据此再次调用工具。原根预算继续使用 `tool-root:<rootId>`，没有新预算域。

## 接口与控制台

`GET /api/workflows/{workflowId}/executions/{runKey}/tool-recovery` 返回协议、是否加入、查询范围、责任说明及该原运行的核验记录。权限沿用 `PlatformPermission.VIEW_CONSOLE` 和 `/me.viewConsole`。四个控制台角色可读，匿名 401，DATA_OWNER / 无能力账号 403；未增加角色解析。接口不返回原工作流业务输出。

工作流的“执行过程”展示“原工具步骤核验”：原 O、授权根、预算、实例 UID、查询轮次、观察时间及原效果。刷新只发 GET。身份、权限、运行切换及读失败会清除旧结果；迟到响应不能恢复为新证据。工作流原 UNKNOWN 与工具效果已确认分别显示，明确不自动派发后续节点。

## 历史兼容与边界

V64 只添加字段及 `workflow_tool_recovery`。旧运行默认版本零，不自动登记查询任务或认领历史效果。迁移前冻结旧步骤和快照摘要，迁移后逐行核对；原 UNKNOWN 行 12、20、批准、UID、原操作和预算保留，不重放。

新代码的旧进度方法只接受版本零，新版本进度必须核对所有者和轮次。该屏障保护平台进度和查询事实，**尚未把 epoch 传到实际执行侧以拒绝新的外部写入**。受控计数已有的原根/O幂等与原子提交合同保持；没有将普通工具、模型供应商或原生任务泛化为同样的效果保证。

发布需先核对队列和底层任务没有活跃操作，排空旧 worker 后再验收新协议。未证明混合旧/新二进制同时写入的生产升级安全。真实业务工具仍需独立的版本合同和效果查询；通用步骤推进、资源责任交接、执行侧 epoch 屏障、取消/补偿及生产灾备仍待。

## 本阶段验收方式

远程回归验证：丢失返回后查询原效果及预算不变、缺记录保留责任、PREPARED 不变为未提交、明确拒绝、原操作拒绝重新认领、指纹不匹配、过期查询者和并发接管、读失败、同 RUNNING 状态下过期执行者不能推进，以及旧进度入口不能绕过新责任。V63→V64 保持旧 UNKNOWN 快照/步骤及版本零。

真实验收使用独立 IMAGE 智能体及公开合成计数对象。隔离故障程序沿原实例身份与工具合同执行，在原存储及 actor 日志已确认后通过 HTTP Hijack 关闭任务连接，产生实际响应 EOF；生产 Runner 镜像不替换。平台只查询同一原效果，不执行后续节点。

真实后端 Pod 更换发生在该工作流已 UNKNOWN、原查询已确认之后，验证持久事实和原预算跨重启保持。租约内进程失联与查询者接管由独立数据库并发测试覆盖；本次在线重启不作为该故障窗口或生产网络分区/灾备证明。全部测试、构建、发布和浏览器在远程完成；模型额度零，最后原实例休眠、授权根和实例身份撤销，预算不重置。
