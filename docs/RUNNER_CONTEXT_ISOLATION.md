# Runner 上下文隔离与取消语义

本契约对应系统审查 R3/R4/R8。发布与验收状态以 [本轮证据](evidence/runner-isolation-20261018/README.md) 为准。

## 普通任务与聊天

普通 `/eap/task` 的模型输入由系统提示词、本次 objective 和显式 context 组成。参考 Runner 不保存全局聊天历史，也不把其他任务或聊天的问答附加到当前任务。工作流需要传递的上游输出仍由 EAP 显式放入任务 context。

聊天请求接受 `message` 和可选 `history`。history 只能是交替的 user/assistant 完整问答，最多40条消息、正文 UTF-8 合计65536字节；不能注入 system 或 tool 角色。省略 history 等同于新对话。该字段是调用者提交的上下文，不是服务端验证过的历史会话凭证。

控制台仅提交当前窗口中已成功完成的问答。失败和结果未知的请求不进入下一次历史；历史超限时按完整问答移除最早内容。切换实例、账号、Agent、卸载组件或点击“新对话”会清空上下文，并使上一代请求的成功、失败和 finally 回调失效。关闭再打开同一实例抽屉可保留当前窗口会话；刷新后不保留。

`GET /eap/state` 返回 `conversationMode: EXPLICIT_V1`，全局 turns 为0。聊天响应的 turns 仅表示本次输入历史加当前问答的轮次，不是持久会话计数。

## 旧实例兼容边界

平台登记的 RUNNER 普通工作流任务，以及平台聊天入口，在模型派发前通过现有运行身份认证读取 `/eap/state`，要求 EXPLICIT_V1。缺少能力声明时明确拒绝并提示升级，不能回落到带全局历史的旧行为。工作流为能力检查唤醒了原本休眠的旧 Runner 时，拒绝后尝试恢复休眠。

新默认镜像只影响后续创建的版本。已有模板、实例及快照仍绑定原版本，必须通过 EAP 创建兼容版本和新实例，再显式更新业务绑定；本次没有迁移、唤醒验证或重放既有样例。自定义 IMAGE/SOURCE 的普通任务协议不因此自动获得参考 Runner 的隔离保证。

## 取消与工作流准入

参考 Runner 的任务串行锁和模型会话串行锁均可被 HTTP 请求上下文取消。等待者取消后立即退出，取得锁后再次检查取消状态和运行身份。出站模型 HTTP 请求传递原上下文，并在发送前再次检查。

发送前确认取消时使用 MODEL_NOT_DISPATCHED；进入 HTTP 发送后遇到取消或传输异常时仍按 UNKNOWN 处理。普通任务已缓存的同键回执保留原结果，不因取消自动重新调用；UNKNOWN 的预算处理也不变，模型调用次数计入已用，无法确认的输出 Token 保持预留。

EAP 网关对携带已登记工作流 taskKey 的模型请求，在同一准入事务中先锁定工作流记录，核对 RUNNING、开始时间和执行期限、最后一个 DISPATCHING 步骤、Agent 及可用的运行实例身份。恢复协议版本1还要求当前 owner/epoch、步骤序号和 TASK_WAIT 阶段仍匹配且运行中。校验通过后再取得预算锁并预留；即使关闭预算功能，也保留这项工作流责任检查。

该检查阻止已经失效的工作流意图再准入，不能撤销此前已获准且可能已经到达供应商的调用。本轮没有新增通用工作流取消 API，也没有宣称任意自定义运行程序都遵守参考 Runner 的任务身份和取消协议。

## 尚未完成

- R5：聊天缺少持久提交键和回执查询；响应丢失后的人工重发仍可能再次计费。“结果未知，请核对观测”只是提示。
- 普通模型任务回执仍为进程内缓存，不能代替跨重启持久回执。
- R9：普通任务明确失败后的统一资源回收仍待独立修复；本次旧能力检查失败的恢复休眠仅覆盖派发前检查。
- 没有真实模型收费验证、旧实例快照迁移、容量压测或长期故障恢复演练。
