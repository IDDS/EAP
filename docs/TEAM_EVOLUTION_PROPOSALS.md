# 团队模型提案（T3-K1 / T3-K2 / T3-K3）

T3-K3 已部署并完成归档核对（2026-10-15）：操作台沿用 T3-K2，补齐提案推理参数及草稿到独立留出的隔离集成验证。真实供应商提案和完整真实 HOLDOUT 仍未验证，详见文末最新记录。

## 用途与边界

原提交者显式请求模型为一个角色生成提示词草稿。请求只包含 `requestKey`、已登记的 `parentId` 和 `role`；服务端从冻结合同组装角色顺序、父候选的两个提示词及公开 TRAIN 样本。VALIDATION、HOLDOUT 的输入和标签不进入提案请求，不接受调用者额外注入的反馈或模型参数。

模型只能返回一个非空 `system_prompt` 字段；重复 JSON 键、尾随数据、多余字段、工具调用、截断输出和原提示词不变均拒绝。平台复制原父配置并只替换指定角色，其他角色保持。输出作为待审草稿保存，不自动登记候选、不执行样本、不修改线上提示词。完成后的正文需单独显式读取，再沿用现有人工候选登记流程；登记候选另计一次合同尝试。回执的 `registered=false` 表示提案接口本身未自动登记，不是对其他独立登记操作的存在性查询。

草稿是有界训练数据生成的建议，不证明质量、完整团队验证或稳定收益。提案不是 GEPA 反馈反思：本阶段没有执行 TRAIN、采集失败反馈或自动搜索循环。

## 独立批准与预算

`eap.team-evolution.model-proposals-enabled` 默认关闭。现有计划经 V82 迁移后保持 `OFFLINE_ONLY`、提案次数和输出上限为 0；没有旧计划扩容或续期入口。

新预算计划可显式选择 `proposalMode=MODEL_SINGLE_ROLE`，在原字段外必须提交：

| 字段 | 约束 |
| --- | --- |
| `proposalUseConfirmed` | 必须为 true，确认父提示词及公开训练样本用于模型提案 |
| `maxProposalCalls` | 1–2，且不超过合同剩余尝试数 |
| `maxProposalTokens` | 每次 64–512 输出 Token |

设原候选验证及独立留出所需调用数为 `E=2×(验证数×最大候选数+2×留出数)`，提案次数上界为 `P`，提案输出上限为 `Q`，原每角色输出上限为 `T`。计划须同时满足 `maxCalls≥E+P`、`maxOutputTokens≥(maxCalls-P)×T+P×Q`。总预算上限仍为 128 调用、32768 输出 Token、工具 0；期限仍为原来的 30–900 秒。没有输入 Token 或金额硬上限。

同一 TASK 根覆盖提案及后续验证/留出，提案归属被修改角色的 Agent，同时受平台与 Agent 共享预算限制。失败、被拒草稿和 UNKNOWN 不退款或抹除原消费。关闭回执的 `proposalModelCalls` 来自真实预算预留记录，所有提案费用进入原根费用汇总。

## 有界提案的推理参数

T3-K3 修订已于 2026-10-14 远程验证和发布，10 月 15 日完成归档核对及规范源推进；四个模型参数用例在专项、全量和隔离 MySQL 中均通过。

新提案沿用单 Agent 反思的既有策略：模型为 `deepseek-flash` 或 `deepseek-pro` 时，原载荷包含 `thinking: {type: disabled}`；其它模型不追加该参数。参数与完整请求一起冻结并参与原意图摘要校验，重复原请求只读取既有回执，不回填或重发旧载荷。该设置仅用于草稿生成，验证/留出仍遵守冻结的运行 profile。它降低既有“全部输出用于推理、正文为空”的风险，不保证生成成功；空正文、截断或用量不明仍按原失败/UNKNOWN 规则处理。

## 原请求与准入

提案先保存原主体、父候选、角色、模型载荷摘要、Trace 和持久责任，并消耗一次合同尝试。保存后只发送一次模型请求，重复原键读回原记录；改变参数或原主体冲突，不自动换键重试。每根同时最多一个未完成提案，UNKNOWN 会阻断后续提案与前沿封存。

发送前复核两个原实例及冻结 profile，沿用[预算准入](TEAM_EVOLUTION_ADMISSION.md)记录的路由器请求触发唤醒竞态边界。Gateway 另校验平台进程内的提案许可、原意图/载荷/期限、两个角色的当前身份 epoch、原发布登记与 Agent 状态、不可变根账户；HTTP 头、Runtime 身份和伪造 Trace 不能取得提案许可。复用原 Gateway 的治理与真实用量结算。进程内许可在 finally 中清除，不跨请求或线程传播。

`PREPARING`、`DISPATCHED` 阻断前沿封存和根关闭。丢失响应或用量不完整保留 `UNKNOWN`，不自动重发，原输出预留保持。进程丢失原责任时，重复**原请求、原参数**在原批准期限之后可把未完成责任记为 UNKNOWN；该路径只核对原记录，不发送模型。GET 始终只读，不替调用者修改状态。期限内完成响应丢失时先按原键 GET，不能用新键推断原请求没有发生。

## T3-K2 操作台合同

预算页面分别确认模型提案用途和总预算，并在冻结预览后第二次确认提交。总调用及输出预算包含提案；旧计划保持零提案额度。每次提案只提交原父代、单个角色和请求编号；不会把页面样本或任意模型参数送入接口。

原提案列表只读元数据；PREPARING、DISPATCHED和UNKNOWN阻断下一次提案与封存。任何提案提交错误都先保留未知结果，原键核对只用GET，不自动重发。正文需明确读取，并与同根父代逐角色核验；未改角色必须完全一致。草稿带入候选表后仍须独立预览确认，读取和填表不自动登记。

任务、账号、能力变化及组件销毁会清除草稿正文；迟到正文响应不得恢复旧内容。单元测试覆盖用途缺失、未知历史、草稿被篡改及账号切换竞态；上线后的四角色权限、真实只读结果及隔离浏览器模型流程仍待核定。真实供应商提案和完整真实HOLDOUT须在明确的支出授权后另验。
