# 原执行观测分页

任务工作台通过 EAP 原执行关联读取证据，不再依赖全平台最近 7 天、前 100 条明细的覆盖报告。此能力借鉴 Kagent 按任务组织信息的展示方式，不涉及 Kagent 安装或运行时接入。验收状态见[本轮证据](evidence/workflow-evidence-20261019/README.md)。

## 接口与关联依据

- `GET /api/workflows/{workflowId}/executions/{runKey}/observations?limit=20&cursor=…`
- `GET /api/workflows/{workflowId}/executions/{runKey}/observations/{id}`

两者先校验原工作流与运行编号确实对应一条执行。通用任务和控制节点通过登记中的 `workflow_execution_id` 关联；AX 通过原任务中的 `workflow_id`、`workflow_run_key`、任务主键及精确任务编号关联。AX 即使尚未写回工作流进度，也能读取已经提交的原登记；冲突的执行关联不会纳入结果。不根据当前 Agent、运行实例、时间邻近或编号前缀推导关联。

页面契约为 `WORKFLOW_OBSERVATIONS_V1`，返回工作流、运行编号、登记操作、原节点序号/编号及 `nextCursor`。所有详情查询在服务端重新校验归属，不能将另一条执行的操作 ID 拼进地址读取。没有匹配的执行或详情返回 400，与既有执行查询的错误约定一致；不存在的执行不返回空成功页。

GET 权限沿用 `PlatformPermission.VIEW_CONSOLE`。JWT 下沿用观测服务的 DEMO Agent 排除规则，先过滤再分页和读取详情。正文仍使用独立的 `VIEW_CONTENT` 接口；新接口不返回目标正文、快照配置、AX 请求或结果正文。资源仍是既有协作可见性模型，没有新增个人私有 ACL。

## 分页与一致性

服务端默认 20 条、最大 50 条，以登记 ID 降序翻页；每次只对当页操作做遥测投影。查询使用原有关联索引，没有新增依赖或数据库迁移。游标编码版本、原执行 ID 和下一页上界，禁止跨执行使用。它是读取位置，不是授权凭据，也不声称防篡改签名；每个请求都重新校验作用域与可见性。

翻页期间新增的更大 ID 不插入已读列表，刷新后读取。分页不是跨请求的数据库快照：迟到提交的旧 ID、可见性变化及证据状态更新仍可能影响后续页。页面如需核对最新状态，应刷新或再次选择原详情。未对百万级登记或高并发历史查询作性能保证。

前端校验响应的执行标识、契约、操作排序、重复 ID 和游标进展。翻页失败保留已读页和原游标，允许原位置重试；切换执行、账号、撤销权限、刷新或卸载使旧请求失效。第一页面读取失败不展示另一执行或全平台的证据作为替代。

## 证据语义

历史没有登记的任务不会在读取时补登记；没有可见记录不代表没有执行、零费用或观测齐全。UNKNOWN 与失败、等待审批分别保留。身份未确认时，实收计数保留为空；没有预占记录不会显示为零或已结算。

控制节点展示原登记及平台检查事件。其登记 Trace 是关联参考，没有实际 Agent Span 的保证，因此不提供“查看原 Trace”链接。其他操作仅在原登记含合法、非零 Trace ID 时提供遥测链接。

两个接口仅执行数据库读取，不派发任务、调用模型/工具、恢复审批、创建预算、修复身份或改写原状态。结构化结果验收、模板/运行环境/冻结版本关系及通用恢复协议仍是后续独立能力。
