# 执行事件后台补发

固定 LangGraph / AutoGen Core 模板的持久 Runner 可以在业务返回后，有限次补发原 SQLite 日志及投递快照。它不重新计算工具、调用模型、派发任务、续期凭据或唤醒实例。普通 SDK 的 `deliver()` 仍是显式调用；旧模板和未登记日志不会被升级为自动补发对象。

## 从业务完成到补发

1. Go Runner 在启动业务 Worker 前，捕获已通过签名配送的实例 UID 和身份代际；环境变量中的手工凭据不能替代这一绑定。
2. Python Worker 执行固定样例，按原规则最多投递三次，再报告一次状态。成功业务只产生一次工具效果。
3. Worker 为新日志登记捕获的原身份并封存日志，禁止继续追加事件。业务失败、进程中途退出、登记写入失败或旧日志不自动登记。
4. 常驻 Go Runner 每 30 秒检查一次，使用此时安装的有效凭据，通过标准输入启动固定补发程序。凭据不落盘，也不出现在子进程参数、日志或任务回执中。
5. 补发程序只打开已有私有日志，校验原 runtime key、框架/版本、UID、身份代际；使用原生产者、事件 ID 和序号。新身份不能接管旧日志。
6. 每轮至多发送一个事件批次及一份报告；事件已经确认时只补报告。原业务回执保持不变，最新快照通过 EAP 投递状态接口读取。

SQLite 文件与目录必须属于当前用户，目录无组/其他用户权限，日志为私有常规文件；符号链接、缺失/未初始化文件和其他进程持有锁的日志不能被补发程序接管。跨进程恢复依赖原私有目录仍然存在，不提供跨主机存储复制或故障转移。

## 限额和停止条件

| 约束 | 当前值或行为 |
|---|---|
| 检查间隔 | 30 秒；休眠中的实例不会被唤醒 |
| 子进程总时限 | 25 秒；单个 HTTP 请求超时 5 秒 |
| 每个日志的后台轮数 | 最多 6 轮；发送前持久预占，进程重启不重置 |
| 每轮 | 至多 64 条原事件、一次事件请求、一次报告请求 |
| 退避 | 首次至少等待 30 秒，随后 30/60/120/240/300 秒封顶；实际受检查间隔影响 |
| 每次检查 | 最多推进 8 份日志；目录最多检查 4096 个条目，超过则整轮拒绝 |
| 临时网络故障、429、5xx | 在上述预算内继续；不新增业务执行 |
| 401/403、409、请求/回执非法、不可分类错误 | 停止自动补发；保留原日志核对 |
| UID / 身份代际不同 | 不发送、不更改原绑定 |
| 身份缺失或已过期 | 不发起后台请求；本功能不申请续期 |
| 投递取消 | 保留取消状态；不等于取消 Agent 任务 |
| 预算耗尽 | 保留 `EXHAUSTED`，不因 Runner 重启而自动重置 |

同一 UID/代际下已由既有授权流程安装的新凭据可用于尚未停止的日志。发生永久错误的日志不会因此重新进入自动循环。保留日志不等于保证最终送达：磁盘丢失、未登记、预算耗尽、永久拒绝和身份失效仍可能留下待确认事件。

## 业务回执与诊断

工具原回执的 `observation.backgroundDeliveryState` 表示 Worker 返回时的登记结果：

- `NOT_ENROLLED`：没有可用的签名身份绑定，不参加自动补发。
- `WAITING`：已登记，等待有界补发。
- `COMPLETED`：事件和这次报告均已确认。
- `BLOCKED` / `CANCELLED`：已经停止自动补发。
- `UNAVAILABLE`：登记未确认；业务结果仍独立保留，不能为了登记日志重跑业务。

后续补发不会回写这份原回执。后台内部还使用 `SENDING`、`COOLDOWN`、`EXHAUSTED`，这些不是服务端事件投递协议的新枚举。

已认证的机器只读接口 `GET /eap/state` 增加 `executionDelivery`：协议 `EAP_BACKGROUND_DELIVERY_V1`、限制参数，以及最近检查的 `state`、`observedAt` 和可用时的 `processed` / `scanned` / `issues`。状态包括 `NOT_RUN`、`NO_JOURNALS`、`IDENTITY_UNAVAILABLE`、`PASS_FINISHED`、`PASS_WITH_ISSUES`、`DIRECTORY_LIMIT`、`PASS_UNCONFIRMED`。异常输出、文件路径、原始 HTTP 正文、UID 和凭据不会进入诊断对象。

这些计数描述最近一轮检查，不是队列深度，也不是所有日志已成功发送的证明。检查被取消、超时或子进程回执无效时明确标记未确认，不能把它当作零待发。

控制台继续展示[最近一次认证投递快照](EXECUTION_DELIVERY_STATUS.md)，不查询运行实例、不续期、不唤醒。是否自动补发取决于运行程序版本、原身份和剩余预算；后台诊断尚未汇入集中队列面板。

## 范围

本实现限于两个固定框架模板及新日志。未实现任意框架创建、跨实例子 Agent 归属、分布式消息关联、通用任务取消/恢复、跨主机队列接管和长期日志保留策略。eBPF 网络/进程线索不能替代同进程逻辑 Agent 的显式上下文。
