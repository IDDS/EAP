# 集成加固后续实施条件（2026-09-28）

本文件是下一阶段实施约束，不代表已经完成迁移或续期。

## 凭证统一与自动续期

现状：外部实例24小时专属凭证，平台托管与隔离任务仍注入旧机器凭证；所有者配置通道在PoC内使用HTTP。只延长24小时有效期无法解决安全配送和旧模板隔离。

实施需覆盖：统一平台/外部/隔离任务三类运行身份；独立授权范围；首次安全引导；短期凭证换发；休眠超过有效期后的重新接入；新旧凭证原子切换；撤销和目录停用的优先级；正在执行任务的回执处理。不得让未知或已执行工具因轮换重新领取。

验收须包括休眠跨过期、换发响应丢失、并发换发与撤销、旧模板迁移失败回退；每个场景都检查任务实际执行次数。先完成协议和迁移兼容设计，再切换默认Runner，不能直接覆盖旧模板环境。

## 认证数据持久化

集群核对：Keycloak单副本，数据仍为emptyDir，使用现有H2数据库；MySQL及任务Redis已有local-path PVC。当前没有执行认证迁移。

不能简单把emptyDir改成PVC后重启，旧Pod替换会丢失现有库。迁移前应在集群内保留一致性备份，验证账号、用户ID、角色、客户端配置与签名键都可恢复，再切换服务；敏感数据库和导出材料只存受限持久卷，不导出到本地、仓库或日志。优先采用受支持的外部数据库作为生产方案；PVC上的单节点数据库仍不等于高可用。

切换前验证旧token仍可校验及四角色新登录；切换后做受控Pod替换，验证数据和签名键保留；准备回退窗口。TLS、备份恢复、节点故障和多副本兼容需要独立验证。
