# 工作流公平调度与阶段画像

本阶段在工作流队列加入申请人等权轮转、等待老化和真实阶段观测。它是调度主线的有界交付；不等于租户资源配额、CPU分配公平、跨全部执行入口调度或Agent优化收益。

## 领取规则与可信身份

只有新提交的工作流纳入V66调度表。服务端使用认证主体的完整身份计算申请人分组；显示用的128字符requester截断不会合并不同主体。执行context中的tenant、priority、weight、approved不授予调度优先权或权限。没有客户端调度写接口。

全局数据库行锁串行化提交登记和领取；持久dispatch_sequence与申请人last_dispatch_sequence在同一事务更新。新队列先选择达到等待阈值的最旧任务，否则选择最久未获领取机会的申请人的最旧任务，时间相同按执行ID打破平局。默认等待阈值60秒，服务器配置限制1–3600秒。候选选择覆盖整个队列，不先截最近100条再轮转。A连续提交130条、B随后提交一条时，B能在A第一次领取后得到下一次轮转机会；真实并发领取仍每次只产生一个原owner/epoch。

生产继续使用单工作进程、非抢占执行；不增加线程，不中断正在执行的任务。老化缓解持续新申请人的插队，但最长等待仍受当前任务时长、队列长度和既有治理结果影响，不保证固定秒数服务。配置变更的完整策略版本审计、可信租户与资源配额、跨异步直提交/实验等入口统一调度留待后续。

历史未纳入队列维持升级前有限FIFO合同。迁移不回填旧运行、旧查询、工具根或预算；幂等重放返回原运行，不重复登记、改申请人组或领取新轮转机会。

## 阶段事实与责任

| 阶段 | 实际覆盖 | 不能据此推断 |
|---|---|---|
| PREPARATION | 校验地址/身份、唤醒、按需短凭证配送及工具准备检查 | 尚未表示业务任务已经完成 |
| TASK_WAIT | 实际HTTP派发至匹配任务标识的回执/未知结果 | 不是纯模型生成耗时 |
| RECLAIM | 显式suspendAfterTask对应的物理休眠确认 | 未确认不能宣布资源可复用 |
| ASYNC_WAIT | 异步提交、准备、业务结果和物理休眠确认的整体等待 | 不伪拆出没有直接观测的准备/模型/回收耗时 |

阶段保存原执行ID、owner、epoch、节点序号和时间；不保存任务内容、凭证或客户端责任提示。开始与结束都锁定原RUNNING且期限有效的责任，结束还校验阶段自身owner。任务HTTP派发前执行准备屏障，失去责任不会继续派发。后续写入失败沿原工作流UNKNOWN合同，不自动重试外部效果。

仍开放但原责任已更换、过期或运行已终止的阶段，只读显示UNCONFIRMED且duration=null；原记录保持，不伪造完成或零耗时。时钟倒退/缺失数据也用null。已确认的过去阶段事实不因后续运行UNKNOWN而改写。

## 只读控制台

GET `/api/workflows/scheduling`使用既有中央`PlatformPermission.VIEW_CONSOLE`，没有角色/JWT特判。四个控制台角色可读，匿名401，DATA_OWNER及无能力主体403；不返回原始工作流输出或秘密。

导航“编排与执行→调度与画像”，路径`/scheduling`。展示当前排队数、历史未纳入队列数、新队列最长等待、最近最多100个有效领取样本的P50/P95、最多100组排队分布及最近20个新运行的选择原因和阶段。分组以摘要显示；空历史画像不回填。等待时间按新提交到领取的服务器时间计量，不叫模型时延，也不能凭该窗口宣称吞吐提升。

刷新后只接受最新请求；权限/读取失败清除旧数据，页面离开后忽略迟到响应。手机适配必须真实浏览器及看图核验，类型/构建通过不代替视觉验收。
