# 工具能力合同与原操作核验

本阶段对应权限治理中的 R1/R2 与恢复中的 R3 查询边界。工具适配范围仍为受控合成计数对象；调度、Agent 性能调优、权限治理三条主线持续保留，不用本阶段替代全系统验收。

## 能力事实

`GET /api/registry/runtime-tools/contracts?instanceKey=...` 返回策略版本、观察时间和工具能力表。控制台查看使用 `PlatformPermission.VIEW_CONSOLE`，前端使用 `/me` 的 `viewConsole`，没有新增角色判断。此接口不授予机器调用权限。

| 能力 | `controlled_counter_increment / poc-counter-v1` | 策略中其它工具 |
|---|---|---|
| 能力来源 | 已实现的工具存储合同 | 仅按策略列出，未登记可信效果合同 |
| 批准来源 | 控制台根授权及逐级收窄委托 | 策略只负责许可领取 |
| 对象范围 | 原根对象、接收实例及参数范围 | 尚未核实 |
| 幂等范围 | 原根授权和稳定操作标识 | 尚未核实 |
| 保留期限 | 随原持久意图保存，无自动过期清理 | 尚未核实 |
| 同标识异参 | 拒绝，409 | 尚未核实 |
| 查询 | 读取原持久意图及存储终态 | 尚未核实 |
| 提交屏障 | 授权、预算、效果在同一事务复核和提交 | 尚未核实 |
| 取消 / 补偿 | 不支持 | 尚未核实 |
| 当前恢复方式 | 仅查询原操作，不自动重试 | 尚未核实 |

工具名称和种类精确匹配：即使 MCP 名称与计数工具相同，也不能继承受控存储的能力。`allowedByPolicy` 只表达当前策略是否启用该入口，不意味着授权链、期限、实例 UID 或剩余额度已经通过提交检查。能力表不使用运行程序声明或 MCP 提示来推定幂等、取消、强撤销和效果保证。

## 查询合同

`GET /api/registry/runtime-tools/scopes/operations?instanceKey=...&rootId=...&operationId=...` 是纯读取接口。必须提供已纳管实例和原规范 UUID；实例须是该操作持有者或原根持有者。查询直接按原唯一键读取，历史记录超出看板最近 30 条仍可核验。

响应保留原操作、Trace、效果标识、提交后计数、合同版本和 `tool-root:<rootId>` 原预算标识，并附观察时间。原授权、工具策略和机器身份撤销后，具备控制台查看能力的人仍可读取历史效果；历史效果不等于当前可再次执行。

- `COMMITTED / TOOL_STORE_VERIFIED`：工具存储确认原效果。
- `REJECTED / TOOL_STORE_NO_COMMIT`：工具存储确认该原操作未提交。
- `PREPARED` 对外继续映射 `UNKNOWN`；查询不重新提交，也不退还预算。
- 记录不存在：返回错误，不能推定未提交，也不生成新操作标识。

前端在身份、权限、实例变化或刷新时清除旧查询结果；失败和迟到结果不能恢复为新的证据。核验按钮只发送 GET，不发送 execute/claim/settle/revoke。核验请求不自动修改工作流 UNKNOWN、资源责任或历史回执。

## 旧身份清单与冻结范围

本轮全局模板枚举与逐作用域枚举一致：58 模板，39 个带旧凭证引用名称，其中任务名30、网关名28、观测名21、配对名9；各类有重叠，不能相加为模板总数。9 个模板在当前 EAP 纳管实例和发布记录中没有引用，不能据此判定全局无人使用。原22旧发布包含失败历史，不能等同在线实例。

盘点只保存环境名称、公开 UID/镜像、配置摘要和状态元数据。挂载文件内容、命令、golden 快照及外部消费者尚未证明覆盖；全局/逐作用域 CLI 一致也不证明上游分页完整性，因此本阶段不具备共享凭证退役条件。下一批迁移必须在保存原 UID、模板/config 摘要、批准来源、原操作与共享预算后，显式创建新专属身份版本并核验消费者停止使用旧凭证。

本轮冻结完整原账本行、原工作流/任务、原部署和原工具授权/效果，不再只保存预算看板整体摘要。在线验收允许一次新增合成工具效果引起平台 TOOL_CLAIMS 增加1及更新时间变化；原账本行其余字段和全部原预占/结算/意图保持，模型/输出消费不变。

## 后续主线

真实业务工具需要逐项建立版本合同及独立效果查询，不能泛化计数工具。R3 后续仍需持久步骤责任、outbox、执行侧旧写者隔离和查询责任交接；取消 ACK、权限撤销、实例休眠不能证明未知效果未发生。原两个 UNKNOWN 工作流继续保存原意图，不用新运行重演它们。

调度继续确定性公平/老化、阶段画像及准备/回收占用核算；Agent 调优继续独立真实任务、冻结评估器和完整成本，再逐步扩大受控变量。旧 GEPA 结果保持 KEEP_BASELINE，未证明稳定收益。分级观测与知识/模型/工作流联合策略仍列入主线后续。

`RUNTIME_REPORTED` 在能力表中表示尚无可信存储适配器的证据等级，工具名称来自策略配置，不证明发生过执行方上报或实际调用。历史证明中 `models.originalCalls` 按模型观测表行计数（原60条），不是60次独立供应商调用的实证；它与账本MODEL_CALLS已用33分别核对，新增模型为0。
