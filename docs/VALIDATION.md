## 本轮发现与处理

### 工作流准入的时区缺陷

在实际环境的 MySQL `+08:00` 会话中，JPA 按 UTC 处理的工作流开始时间被普通 JDBC 读取为提前八小时。预算准入把新工作流误判为过期，模型调用前即返回 HTTP 400；阶段报告也把当前阶段误标为 `UNCONFIRMED`。原任务因此保留 UNKNOWN，下游未派发，没有产生新的模型账本记录。

新增 `WorkflowBudgetTimezoneMySqlIT` 在独立 MySQL 上复现三项问题：有效任务被拒绝、明确准入拒绝仍标为未知、当前阶段显示错误。修复将这两处 JPA 时间读取统一为 UTC，并将 `workflow_not_running` 这一派发前拒绝标为 `REJECTED`。修复前 3 项失败，修复后 3 项通过。

这项修复不重写历史执行，不把原 UNKNOWN 变成成功，也不对原任务进行重放。

### 历史占用与自动回收

修复后，第一条新任务完成计算与结构校验，但已有全局 `LEGACY UNKNOWN` 占用触发 `SKIPPED_BUSY`，自动回收未进行，系统保留输出并停止下游。这是已实现的保守保护规则；本轮没有清除历史标记或弱化隔离。

另建独立的 `11 + 13 → 核验` 计划，采用原生 Runner 与 Kagent ADK，关闭自动挂起并在结束后通过 EAP 显式收尾。计划成功，原结果为 `{"sum":24}` 与 `{"verified":true}`，两项结构校验通过，2 次模型调用与 10 个输出 Token 全部结算。四角色元数据访问与内容权限的 200 / 403 对照通过。

包含前一条受自动回收保护而停止的任务，本轮共新增 3 次模型调用、15 个输出 Token、0 次工具调用；6 个新实例最终全部挂起并撤销连接。原记录、原计划和 UNKNOWN 保持。历史 UNKNOWN 的归属确认和回收仍是运维限制，不能把这次成功理解为自动回收问题已经解除。

### 测试配置与过时夹具

- MCP 专用构建会禁用普通模型入口，应运行协议与身份测试；完整模型路径由原生和 Kagent 构建分别覆盖。
- 旧镜像兼容性测试缺少模型完成原因，并假定当前 Runner 仍隐式继承之前任务的聊天历史。修正后验证正常完成原因、默认模型参数、原业务输出及现有 `EXPLICIT_V1` 隔离语义。
- 所有 MySQL 专项共用一个库时，其他测试留下的排队任务会干扰调度断言。失败的两类分别在独立空库复验后通过，原失败报告保留。
- 一次修复验证复制到了错误的目录层级，因此仍测试旧源码；随后增加实际编译路径的逐文件 SHA256 校验，原失败记录保留。

## 如何复验

在远程开发或 CI 环境分别执行后端 `mvn -B test`、前端 `npm ci` / `npm test` / `npm run build`。后端普通测试使用独立 H2 上下文，不代替 MySQL 专项。

`*MySqlIT` 需要独立、仅监听回环的 MySQL。测试 URL 有显式安全前缀检查；时区用例要求 `connectionTimeZone=Asia/Shanghai` 和 `forceConnectionTimeZoneToSession=true`。不同专项需要各自干净的数据库，不能连接现有业务库。

Go 竞态测试需要 C 编译器。原生 Runner 和 AX 的测试按各自目录执行；Kagent 使用固定 `go.mod` / `go.sum` 和 `kagent` 标签。MCP 夹具标签分别为 `mcphttpfixture`、`mcpfixture`，选择 `TestMCP|TestIdentity`，并提供 Python 观测组件。双版本兼容测试需要通过独立摘要核验的原版本二进制；这些内部镜像产物不在源码包中分发。

交付工具使用 Python 标准库测试；提示词优化组件另有固定依赖。不要把旧验收脚本、已完成任务或原 UNKNOWN 当作可重复执行的测试夹具。
