# 身份配送后的休眠恢复

实例的凭证安装成功与实例恢复休眠是两个独立事实。此前，凭证确认事务已经提交后，`finally` 中的一次休眠 RPC 若遇到 Substrate 操作占用，部署就会失败；重试原创建请求又可能因为身份已经 READY 而跳过配送，未复查实例状态，最终把仍在 RUNNING 的实例报告为已休眠。

## 修复后的行为

- 只对 `ABORTED` 且说明为 `another operation is in progress for this actor` 的明确拒绝执行有界重试。最多四次休眠 RPC，两次之间等待 250 毫秒。
- 每次尝试前检查原 UID、模板、空间及实例名称；已确认休眠时直接完成。RPC 返回成功后，再核对原身份及实际休眠状态。
- 不重试凭证配送、唤醒、任务、工具或模型。超时、权限错误、其他 ABORTED、非休眠回执等保持失败，不把未知结果当成可安全重试。
- 线程中断立即停止并保留中断标记。若配送自身已经失败，保留原始错误，恢复失败附加为次要错误。
- 平台创建流程在身份 READY 后还会独立核对原实例身份及 SUSPENDED 状态。包括原请求重放；不会为了得到成功响应而暂停一个仍在运行的实例，也不会新建版本或重新签发身份。

## 恢复边界

这是原先处于休眠状态、因身份配送而临时唤醒的实例收尾。原先已经 RUNNING 的实例不因配送检查而被休眠。超过尝试上限时保留原请求与已确认身份，等待核对；操作者应先确认原实例和在途任务，再通过 EAP 完成必要控制并重试原请求，不能换键新建来掩盖失败。

身份的前后检查不等于原生 RPC 支持带 UID 的原子条件控制；也不提供跨实例接管、通用业务恢复、取消或补偿。未扩展旧共享凭证握手路径，也不将任意运行时错误解释为同一可重试冲突。

## 验证

隔离原实现的两条专项用例分别复现“瞬时占用导致失败”和“身份 READY 掩盖实例未休眠”。修复后身份配送29项、创建10项以及完整后端1426项/149类通过；MySQL8.4.11上两个专项39项再次通过。专项是全量子集，不重复累计。

覆盖连续占用、非占用错误、替换 UID、休眠回执和实际身份不一致、并发已完成休眠、线程中断、失败错误保留和原请求重放。已发布到远程 PoC，LangGraph/AutoGen 的新实例创建、实际休眠及同请求重放通过，见[验证范围](VALIDATION.md)与[验证记录](VALIDATION.md)；故障分支在隔离环境注入，不等于对生产进行了故障注入或长稳验证。
