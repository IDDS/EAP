## 登记与预算

新任务登记 TRAIN/VALIDATION 各 1–3 条，HOLDOUT 1–10 条，合计最多 16 条。规范化输入全局去重，任务组不得跨切分。整根准入上限不超过 64，输出 Token 上限不超过 65536。GEPA 0.1.4 用 reflection_minibatch_size=1，使 3 个验证样本、原训练评估 1、新训练评估 1、新验证评估 3 能在 8 次样本评价内完成。参见 [官方固定版本 API](https://github.com/gepa-ai/gepa/blob/v0.1.4/src/gepa/api.py)。样本评价次数不是模型调用数；每次配对生成两份实际输出。

计划最坏调用数 = 2 × maxMetricCalls + 2 × validationCount + 4 × holdoutCount + reflectionCalls（GEPA 固定上限 2，SIMPLE 为 0）。计划最坏输出 = 非反思调用数 × maxTokens + reflectionCalls × 512。3/3/10、8 次评价、每次128输出时为64次/8960 Token；8192不足。先检查原 PLATFORM/AGENT 账户已用、预留、margin 与违规状态，再读取运行profile/建立新根。预检是容量快照，后续每一次实际调用仍需原实时预占与结算；它不是整计划预占，不保证并发业务不会先耗尽余额。不能提高旧根额度、退还既有消费、清零账本或绕过网关。

V67 仅新增 agent_optimization_protocols 与 agent_optimization_holdout_batches，不修改旧任务、旧实验和旧预算列，也不回填旧root。版本1登记完整主体摘要、计划上限、留出条数/任务组数；展示主体可截断128字符，幂等指纹保留完整认证主体，不能因相同显示前缀跨主体复用任务。

## 封存、持久批次与未知处理

Worker context 只有训练和验证。反思仅使用已经持久化且用途获批的训练轨迹。候选完成原全量验证后，在同一事务封存chosen_digest、使搜索claim失效，并按留出 sampleId 固定排序，分别为 MANUAL/SELECTED 持久登记每批最多3条的计划。10条对应每臂4批，共8个逻辑批次。

操作键固定包含原root、候选摘要、HOLDOUT和有序原sampleIds。每批evaluation_id与原子实验绑定，调度重入、并发或服务重新读取都先查原意图，不用内存游标。提示词相同可跨逻辑臂引用同一原评估；逻辑计划仍完整，实际成本只统计一次。未知回执、缺usage或违规会停止原根并保留基线，保留未执行样本与原预留；不换键、不重放、不创建替代根。FAILED/UNKNOWN只查询原记录，不修改失败成为成功。

旧协议任务保持原小样本路径，evidence.protocolVersion=0，不虚构新增登记和多批留出。历史结论按其原合同展示。
