# Kagent / Go ADK 内部执行观测

EAP 的可选 Kagent Runner 将实际 Go ADK 生命周期回调转换为[执行事件](AGENT_EXECUTION_EVENT_CONTRACT.md)。观测与模型、工具执行分开：模型仍经过原治理网关，工具仍必须完成 check、claim 和 receipt；观测不能创建执行许可，也不能重跑原任务。

## 覆盖范围

固定依赖为 Kagent `v1.0.0-alpha14` 的 `673d181ec269` 提交和 Go ADK `v2.5.0`，不随上游自动升级。

| 对象 | 记录与边界 |
| --- | --- |
| 实际 ADK Agent 调用 | `RUN_STARTED`，以及经调用方确认的 `RUN_FINISHED`；每次调用分配新的 UUID |
| 同进程子 Agent | 从实际注册的 `SubAgents()` 树确定父定义，再关联本次仍在执行的父调用；不按 PID、名称相似度或时间推断 |
| 串行、并行、重复子调用 | 有界适配器支持不同子定义并行和同一定义串行重复；同一定义同时重入、未知定义及跨 invocation 混用标为捕获不完整 |
| 实际 ADK 工具回调 | 工具开始与确认成功结束；独立观测 UUID，不把模型的 function-call ID 当成 EAP 工具许可 |
| 错误或未知回执 | 无法确认的工具结束保持缺口；业务 UNKNOWN 不伪造成功或失败结束 |
| 动态代码 | 本适配器不登记代码正文或摘要；Python 临时代码能力仍由原[专用实现](EPHEMERAL_EXECUTION_OBSERVABILITY.md)提供 |

现有零代码 Kagent 配置仍只开放单 Agent 文本轮次和 `CALCULATE_SUM_V1`。适配器对真实 ADK 子调用的支持，不等于控制台已经开放任意 Kagent 子 Agent 编排；AgentTool 递归、跨 Agent 转移、通用 workflow 节点、恢复激活与任意工具注册也不在此契约内。

## 元数据日志与投递

每次 invocation 使用独立 producer 日志，位于原 `EAP_TOOL_JOURNAL_DIR` 下的 `kagent-events`。目录为 `0700`、文件为 `0600`。事件先写入不可覆盖文件并同步到磁盘；日志只存逻辑 ID、父子关系、受控定义名、时间、PID、Trace 和结果类别，不写提示词、输入输出、源码、异常正文或凭证。

只有可信身份配送已安装、投影一致且未过期的实例能创建和发送日志。日志冻结运行实例、Actor UID 与身份代际；发送时重新取得同一身份的当前凭证。续期可继续投递，换 UID 或身份代际不能接管旧日志，手工环境变量凭据也不能启用自动投递。

完成调用会唤醒后台投递器，另有 30 秒周期检查；网络请求不持有捕获回调的锁。后台只访问 `execution-events` 与 `execution-delivery` 观测接口，不执行任务、工具、身份续期或生命周期控制。

- 每次调用最多 64 条事件，注册树最多 16 个定义；本地最多保留 256 个调用目录。
- 每次扫描最多处理 8 个待投递日志，整轮最多 20 秒、单请求最多 2 秒；单日志最多持久记录 6 次投递尝试。
- 回执丢失时先重发原批次及原事件 ID，确认后再发送后来追加的事件。重新启动只读取原日志，不依赖内存确认位。
- HTTP 429、5xx 和网络故障在剩余次数内补传；重定向、其他非成功状态和无效成功回执停止该日志投递。
- 回执必须确认相同条数、`recorded + duplicates == received` 及稳定的服务端 streamKey。
- 进程中途退出留下的已完整写入事件可以补传，缺少结束回调仍显示不完整；损坏文件拒绝发送。
- 满容量不自动删除历史；捕获失败不改变原模型或工具结果。需要保留日志卷并安排独立归档与保留策略。

`/eap/state.executionDelivery` 提供最近一次捕获或后台检查状态及限制。中央状态使用既有 `POST /api/runtime-access/v1/execution-delivery` 协议，按原 producer、实例 UID 和身份代际发送元数据快照。控制台分别展示报告总数、客户端已确认、客户端待确认、服务端已接收，不能互相替代。

状态报告保存在同一日志的私有 `delivery-reports` 子目录；报告正文、每次发送意图和成功回执分别不可覆盖写入。报告回执只确认快照，绝不生成事件回执。报告失败也不停止原事件在自身额度内的补传。

- 每个日志最多16份状态快照，每份最多3次持久发送尝试；报告请求不计入累计事件投递次数。
- 未确认快照冻结原序号和正文；即使后来事件已确认，也须先补原快照，确认后才推进新序号。重新打开日志继续原意图。
- 429、5xx及网络故障有限补发；401/403、409、重定向、其他拒绝和无效成功回执停止报告。耗尽次数不自动换序号绕过限制。
- 成功回执须包含同一序号、有效且一致的 streamKey 和明确布尔值 duplicate；额外 data 字段、缺项、超长内容均拒绝。
- 快照没有变化时不发送心跳、不刷新报告年龄。身份无效时可能无法上传最新受阻状态，中央最后一份报告仍是历史快照；超过5分钟和已撤销身份由现有界面提示。
- 已有旧事件不会被回填推测的报告；旧格式停止标记仍可读取为传输受阻。损坏报告历史停止报告，不把它当成事件确认。

投递全部确认只表示日志中已写入事件被确认。业务 UNKNOWN、进程中断或捕获失败仍可能缺少结束事件，结构缺口以执行图为准；中央快照不是实时队列或完整业务证明。

网关的工具 `REQUESTED` 遥测与守卫的 `SUCCEEDED` 回执是两个不同阶段，可能各占一行；不能把遥测行数直接当成执行次数。实际执行次数应结合守卫领取与回执、原任务和执行事件判断。

## 查看方式

控制台“运行与观测 → 执行关系”可按 Agent 查询已收到的 `kagent-go-adk` 事件流，查看逻辑执行、同流父子关系和工具调用，并在投递状态面板核对四项独立计数。事件报告的 PID 只是进程属性；多个子调用可以共享同一 PID，短调用结束后仍保留自己的逻辑 ID。

现有镜像和实例不会自动升级。发布时须构建新 Kagent Runner 镜像，配置不可变摘要，并由 EAP 创建新版本；实际部署与验证状态以[验证范围](VALIDATION.md)和[验证记录](VALIDATION.md)为准。

实现依据：远程缓存中锁定的 Go ADK 2.5.0 `plugin/plugin.go`、`agent/agent.go` 与 `agent/context.go`（核对日期 2026-10-26）。对应上游[插件接口](https://github.com/google/adk-go/blob/v2.5.0/plugin/plugin.go)和[Agent 生命周期](https://github.com/google/adk-go/blob/v2.5.0/agent/agent.go)。`AfterAgentCallback` 不能单独证明业务成功，因此根调用结束以 EAP 原结果校验为准。
