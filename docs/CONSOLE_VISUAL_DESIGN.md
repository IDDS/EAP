# EAP 控制台视觉约定

2026-09-29，依据用户要求增强科技感并参考 AdminLTE；默认深色导航、浅色工作区，运行大屏仍使用独立展示样式。

- 色彩：导航 `#0c1c2b`，工作台标题/容量概览深蓝，工作区 `#f0f5f8`，强调 `#087f9a`，正文 `#193246`，辅助文字 `#52697b`。危险、警告、成功保留各自状态含义，不能用强调色替代。
- 层级：导航和面包屑定位 → 页面标题和主要操作 → 指标/筛选 → 业务表格。工作台三个行动入口作为一组，避免重复阴影与装饰边框。
- 图标：Element Plus SVG，用于已有功能入口和可识别的指标；装饰图标 aria-hidden，含义同时以文字显示。不得用依赖字体的特殊字符绘制硬件图标。
- 数字：指标使用 tabular-nums，保留单位、数据来源、查询时间与缺失说明。无采样不得显示为 0，不制造增长百分比、随机波形或在线数量。
- 字体：优先 Aptos / PingFang SC / Noto Sans CJK SC / Microsoft YaHei，使用本机可用字体，不发起外部字体请求。保留原字号选项。
- 交互：保留菜单当前状态、键盘 focus-visible、44px 移动导航、窄屏文字抽屉；prefers-reduced-motion 下缩短动画。样式不能掩盖禁用、加载、错误及权限限制。
- 实现：`frontend/src/styles/console.css` 在旧样式之后导入，集中定义本轮主题；不要继续把主题散落追加到旧 styles.css。新增页面复用这些 token，逐步迁移旧硬编码颜色。
- AdminLTE：已安装 @adminlte/vue 0.7.0，运行大屏使用 LteCard/LteSmallBox/LteInfoBox；参考 AdminLTE 控制台结构和主题变量方式，保留 Element Plus 表单/弹窗，无新增依赖或全局 Bootstrap 覆盖。
- 范围：这一轮不是全站深色模式，不改变业务、权限或接口合同，也不代表生产集成验收完成。

参考：[AdminLTE Vue](https://docs.adminlte.io/vue/introduction)、[主题](https://docs.adminlte.io/vue/theming)，访问日期 2026-09-29。


## 企业工作区细化（2026-10-16）

用户要求继续完善前端，并参考经典设计或已有系统风格。以本文件既有 AdminLTE 方向为基础，采用稳健企业风：深色导航、浅色内容、青色强调。此方向为沿用现有约定的实现选择，并非用户新选择了一套外部品牌。

参考资料访问日期均为 2026-10-16：

| 参考 | 借鉴点 | EAP 中的落点 |
| --- | --- | --- |
| [AdminLTE Vue 主题](https://docs.adminlte.io/vue/theming) | 以主题变量组织既有后台界面 | 保留深导航、浅工作区、原图标和 Element Plus；集中维护 console.css |
| [IBM Carbon 数据表规范](https://carbondesignsystem.com/components/data-table/usage/) | 标题、工具栏、行内容各司其职；给表格充足宽度 | 统一标题/辅助文字/操作区，评估表格保留完整内容宽度 |
| [AWS Cloudscape 表格资源视图](https://cloudscape.design/patterns/resource-management/view/table-view/) | 资源选择、操作与空状态有清晰语义 | 先选择数据集，再录入、标注、校准；选中态和禁用态明确 |

这些是设计规则的参考，不代表引入了 Carbon/Cloudscape 组件或通过其认证。保留现有 npm 依赖、中文本地字体、权限和 API 合同；没有外部字体请求或装饰性假数据。

- 工作区背景使用中性 `#f4f6f8`，白色表面、`#d7e2e9` 边框；原青色 `#087f9a` 和状态语义色保持。
- 页内标题 24px、辅助说明 13px；面板标题 15px；既有全局字号偏好继续生效。使用 8px 间距体系，面板内边距 20px、手机 16px、基础圆角 6px。
- 减少阴影与渐变：按钮依靠色彩、边框和位置表达主次，正文面板用轻边框分隔。主工作台保留深蓝头部，运行大屏保留独立风格。
- 评估页签增加简短用途说明，桌面四项并排、手机两行，避免横向隐藏入口。指标采用连续分隔栏，数字使用等宽数字特性。
- 数据集选择使用原生 button，`aria-pressed` 表达选中状态，Enter/Space 均可操作；提交/读取时对应禁用，不用纯视觉伪装。
- 录入组件继续挂载，切换评估页签保留原状态。未打开时只显示紧凑入口；打开后按样本身份、内容、来源引用组织。来源核对的真实含义和限制继续可见。
- 只有确实能打开详情的表格显示可点击行；普通目录、标注和汇总表不再暗示整行可点击。

第一批落地范围为共享控制台主题、质量评估与反馈页标题。设计验证范围、候选/上线状态与截图以 [本轮证据](evidence/console-design-20261016/README.md) 为准，不把设计方案视为全站功能验收。


## 目录与详情工作区（2026-10-17）

沿用上一节的 AdminLTE / Carbon / Cloudscape 参考，继续完善资源管理界面。此次为既有设计规则的实现延续，没有新增外部设计系统、字体或依赖。

- 目录使用紧凑的浅色标题区，将深蓝视觉重点留给工作台。五项概览桌面连续排列，手机采用两列加底部待办行，首屏能够看到搜索与第一条资源。
- 搜索与四类状态筛选都有持久标签。状态筛选使用原生 details，折叠时保留“已设置筛选条件”提示；明确区分组织范围概览与筛选后的列表计数。
- 桌面保留完整表格，手机使用分隔列表，同一 page.items 和分页状态驱动两种显示；责任、六项状态/事项与证据均保留，不为窄屏隐藏风险信息。
- 详情的身份线索和接入进度可展开。setup=1 入口继续展开接入指引；各详情入口允许换行，原深链接保持。
- 详情入口采用原生按钮与 aria-pressed 表示当前视图；容器是带名称的 group，避免只声明 tablist 却未实现完整 ARIA Tab 行为。
- 浅底指标栏必须同时设置数字、标签和图标颜色，不能继承旧彩色卡片的白色标签。详情页标签使用 --console-muted，移除装饰性侧色条，按实际渲染验证文字对比度。

本轮只更新 AgentsView.vue、AgentDetailView.vue 与集中主题 console.css；两个视图 script 块保持原样，业务 API 与 /me 权限规则保持。实测结果、失败记录及上线状态见 [设计发布报告](evidence/agent-workspace-design-20261017/README.md)。


## 治理工作区（2026-10-17）

继续沿用现有企业控制台风格，缩短从页面入口到治理操作的距离。

- 四分区采用原生按钮与 `aria-pressed`，桌面四列、手机两列；紧凑状态栏持续展示执行模式、网关、启用策略和待审批数量。
- 总览先展示所选时间范围内的事件指标；执行明细、控制链路和接入说明置于原生 `details` 中。网关未配置提示保持跨分区可见，空事件提示只在总览显示。
- 预检表单排在风险分布之前，DOM、键盘与视觉顺序一致；桌面双列，小屏单列。切换分区保留未提交内容，原 policyId/eventKey 深链接保持。
- 策略列表优先显示名称、版本、范围和操作，规则 JSON 按需展开；编辑器与审批业务规则不变。
- 浅底指标条明确设置深色标签、较小图标；手机的分区、状态和指标均为两列。不得用缩小文字替代信息层级整理。

本轮三个源码文件为 GovernanceView.vue、GovernancePolicies.vue 和 console.css；两个 Vue 文件的 script 内容保持。具体测试、失败与发布记录见 [治理工作区报告](evidence/governance-workspace-design-20261017/README.md)。


## 审计记录与详情（2026-10-17）

- 表格行可点击时仍提供明确的详情按钮；按钮名称包含记录 ID，键盘可直接打开详情并返回原入口。
- 手机以同一分页数据渲染记录列表，保留动作、时间、结果、操作者、资源与 Trace；搜索、状态、排序及分页仍共用 HistoryTable 的请求状态。
- 可选 mobile 插槽只改变展示，未提供该插槽的历史表格保持原行为。不得为响应式列表发起第二份查询。
- 详情抽屉宽度不超过视口，元数据与变更正文分区，长标识及 JSON 可换行；缺失正文显示“未记录”，不能用虚构的空 JSON 代替。
- 审计抽屉沿用其他抽屉的 `append-to-body`、z-index 4000，确保高于固定顶部导航；验收需要检查关闭按钮实际命中，不能只检查 DOM 可见性。
- 未知结果保留原值并使用中性标签；正文坚持文本插值，含 HTML 的审计字符串不得作为标记执行。

本轮范围为 AuditView.vue、HistoryTable.vue 与 console.css；两个 script 块保持。验证及部署状态见 [审计工作区报告](evidence/audit-workspace-design-20261017/README.md)。

## 团队与计划工作区设计（2026-10-22）

面向配置多智能体任务和核对执行结果的运营人员。主要阅读顺序是团队 → 计划目标 → 有序步骤及成员 → 结果要求 → 执行证据。参考 [Impeccable 的产品界面设计方法](https://impeccable.cn/designing/)及 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)，访问日期 2026-10-22。前者作为设计参考，未安装其 CLI、Live Mode 或与既有同名 skill 相互覆盖。

采用已安装的 `frontend-design`、`web-design-guidelines`、`vue-best-practices`。视觉决定继续服从本文件已有产品方向；Vue 技能不触发全项目代码风格重写。

- 基础色：导航 `#0c1c2b`，画布 `#f4f6f8`，表面 `#ffffff`，正文 `#193246`，辅助文字 `#52697b`，强调 `#087f9a`；边框及语义状态色复用现有 token。
- 字体：继续使用本地 Aptos / PingFang SC / Noto Sans CJK SC；页标题 24px、当前计划 20px、面板标题 15px、内容 14px。顺序号使用等宽数字，用户目标和长能力名称允许换行。
- 布局比较：原来的三个全宽表格将目标、分配和执行分隔；改为左侧计划选择、右侧当前计划工作区。所有正文左对齐，避免表格操作需要横向寻找。

```text
原结构                         采用结构（桌面）
团队选择                       团队选择
全部计划大表                   计划列表 | 当前目标、状态、上下文
全部步骤大表                            | 有序步骤、成员、结果契约
执行面板                                | 提交入口、执行证据
团队资料                       团队资料（按需展开）

手机：团队选择 → 紧凑计划列表 → 当前计划 → 有序步骤 → 执行证据
```

设计复核：左栏宽度用于在计划间切换，右侧顺序号表达真实串行步骤；不增加无数据依据的指标卡。保留关键风险说明、未知状态和只读权限反馈。手机重排同一份步骤 DOM，避免并行两套表单状态。选择按钮支持键盘及 `aria-pressed`，字段有持久标签，长内容不能挤出操作区。实现及验收状态另见本轮工作记录，本节不是上线证明。

## 全控制台逐页优化约定（2026-10-23）

按[24页清单](CONSOLE_PAGE_OPTIMIZATION.md)逐一检查桌面与手机。保留工作台、目录/详情、计划、评估和治理的主要结构；统一新增页面的标题、说明、间距和语义颜色。分析摘要控制篇幅，仅在相关总览展示，避免录入或预算页重复大段概览。

- 多分区使用 `SectionNavigation` 的原生按钮、可见焦点与 `aria-pressed`；不声明未实现键盘协议的 ARIA tab。
- `PageControls` 给每页条数提供持久标签，翻页和条数变化继续由页面或列表组件拥有状态，不增加数据请求来源。
- 业务/异步任务手机端以记录块显示同一份查询结果，保留业务结果、实例身份与未知状态。
- 表单或确认按钮按 `/me` 能力控制；确认等待期间再次核对权限、账号与所选任务。
- 策略启用只能表述为“已配置”，风险数量不换算成无分母的百分比；读取失败不展示默认零值作为结论。
- 弹窗限制在视口内，任务确认框置于对应抽屉上方。大屏保留深色体系，认证回调提供清楚的失败恢复路径。

本节说明实现规则，实际构建、上线和浏览器验收结果以逐页清单所链接的最终证据为准。

实现边界：OrchestrationView 继续拥有选择、请求及权限状态，WorkflowOutputConfig、ExecutionTimeline、PlanOutputs 保持各自配置/证据职责。仅增加派生的分配计数、中文状态呈现和带请求序号保护的读取状态；后台轮询保留上次证据，读取失败不显示为空列表。没有按角色名做授权判断，也没有新业务写接口。

手机实测发现长团队名会把浮层撑出视口，给团队与成员 Select 设置专用 `popper-class`，在集中主题中约束宽度并允许选项换行；保留完整标签。按 [Element Plus Select 文档](https://element-plus.org/en-US/component/select.html) 的浮层扩展方式实现（访问2026-10-23），不影响其他页面选择器。复验直接检查展开状态，并保留首次597px弹层超出390px视口的失败证据。
