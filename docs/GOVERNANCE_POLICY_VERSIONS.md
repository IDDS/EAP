# 治理策略版本、并发编辑与显式回退

2026-10-12，T8-A 已部署并完成有界验收，Flyway81；790 项应用源、18 路径在证据接收核对后已精确推进远程基准。本文不表示知识、模型、工作流的统一策略主线已完成。

此前 `/api/policies` 保存会覆盖当前规则，缺少历史及编辑版本校验。本轮为同一入口增加不可变版本记录、并发冲突检查和回退发布；现有预检仍读取当前策略，新增决策同时保留命中策略版本。

## 行为合同

- 新建策略写入版本 0 的 `CREATED` 快照。`governance_policies.revision` 由 JPA 乐观锁维护；历史表按策略 ID 和版本唯一。
- 原有策略迁移后为版本 0，不在迁移或读取时伪造历史。首次真实修改在同一事务记录此前 `BASELINE` 和新 `UPDATED`；页面明确首次记录以前的历史不可得。
- 编辑和启停必须携带读取时的 `expectedRevision`。缺失或负数为 400，版本过期为 409。两个真实事务同时提交同版本只能有一个成功；当前行先 flush，随后追加快照，任何一步失败整笔回滚。
- 名称、范围、类型、规则、模式和启用状态都纳入快照。JSON 对象键顺序及空白不构成新规则；数组顺序保留。无内容变化时不改版本、更新时间或历史，也不因数据库 JSON 格式化触发隐式更新。
- 快照含内容 SHA256、可信认证主体的 SHA256、数据库记录时间和变更类型；回退另含来源版本。摘要用于内容核对，不是签名或数据库管理员不可篡改证明。
- `GET /api/policies/{id}/versions` 返回当前版本及最近 50 个历史版本，超过时显式提示截断。更早已记录版本仍存储；没有历史的旧策略读取为空。
- `POST /api/policies/{id}/rollback` 必须包含 `expectedRevision`、`sourceRevision`、`sourceDigest`。来源必须是此前已保存的较早版本，摘要不符或当前版本变化拒绝；回退产生新的 `ROLLED_BACK` 版本，保留所有旧记录。同内容回退拒绝，不伪造发布。
- 新预检决策写入命中策略版本；旧决策和审批重读保持原结果，旧 JSON 缺少版本仍显示“版本未记录”。本轮不自动撤销既有审批，不回填决策历史。
- 前后端仅使用中央 `VIEW_CONSOLE` / `GOVERNANCE` 能力。页面编辑保存携带原版本，回退须先核对再确认；冲突或断线后清空旧表单/历史，不自动读取新版本重发。账号、能力、筛选和卸载清除旧数据，迟到响应不恢复旧事实。
