# 任务工作台（更新于 2026-10-22）

入口为首页“跟进任务”或“编排与执行 → 任务工作台”，路由 `/task-workspace`。借鉴 Kagent 围绕一次任务组织信息的方式，由 EAP 提供执行与证据；本页面改造本身不安装 Kagent，也不证明其运行时兼容性。

## 当前范围

- 默认展示跨工作流、团队计划、独立 AX 和本人试运行对话的执行目录，支持历史分页、类型、状态、时间、名称/原编号/发起人编号及“仅我发起”筛选。工作流内的 AX 步骤保留在原执行中，不重复计入独立任务。
- 工作流详情侧栏仍提供最近 20 次快捷选择；完整历史从执行目录查询。进入默认目录不会自动打开第一条工作流。
- 深链接包含 `workflowId` 与 `runKey`，刷新保留原执行；可按原编号查询更早记录。
- 中间展示原状态、受权限保护的步骤结果、实际步骤及原工具核验。右侧展示申请人、时间、原执行编号与关联观测。
- 结果需要用户点击读取，仅 `/me` 返回 `viewContent` 的账号可操作。切换任务、身份或撤销权限会清除结果；晚到响应不能覆盖当前任务。
- 执行读取失败时清空详情并显示错误，不以最近成功记录替代。UNKNOWN、失败、等待审批分别展示。
- 所有本页业务请求均为 GET。刷新、查询、核验不会重放原执行、领取新预算或恢复后续步骤。

## 执行目录合同

`GET /api/executions` 返回 `EXECUTION_CATALOG_V1`。`kind` 支持 `ALL/WORKFLOW/PLAN/AX/CHAT`，`status` 支持 `ALL/ACTIVE/SUCCEEDED/ATTENTION/UNKNOWN/FAILED`；`query` 最长 128 字符，百分号和下划线按字面搜索。`from` 包含起点、`until` 不包含终点；`page` 为 1–10000、`size` 为 1–50，且 `page × size` 不超过 10000；控制台每页 20 条。响应返回 `windowLimit=10000`，超出窗口时应缩小时间或任务范围。还支持 `mine` 和可选 `workflowId`。

工作流/计划/AX 按 Hibernate 的 UTC 时间读取和筛选；对话沿用原 JDBC 回执的时间语义。各源先转换为 `Instant`，再按创建时间倒序、类型及原编号合并分页，避免东八区会话下偏移 8 小时。每源最多读取当前有界窗口的候选元数据，不读取正文。分页反映查询时的数据，不是跨请求冻结快照；没有大规模数据集的性能承诺。团队计划只按原工作流 ID 和原运行编号精确关联。工作流与独立 AX 沿用现有可见范围，尚未实现项目级资源隔离。

本人对话要求 `/me` 的 `operateInstances` 能力，并按后端身份匹配原回执所有者；管理员也不能通过目录查看别人的对话。目录不返回提示词、回复正文、执行快照或所有者摘要。过期且未确认的对话显示 UNKNOWN，仅作查询投影，不修改原回执。点击对话读取原回执；独立 AX 跳转原任务详情；工作流和计划打开原执行。

切换账号、撤销能力、切换筛选或卸载页面会清除旧记录与回执，迟到响应不能覆盖当前页面。修改尚未提交的筛选不改变当前分页范围。

## 结果与诊断

原执行详情显示按状态区分的下一步说明。UNKNOWN 提示核对原效果，审批、阻塞、结构不合格与失败分别说明；这些说明不提供未经工具协议支持的恢复或补偿操作。结构结论只汇总已配置契约，流程完成、结构通过和业务正确性分别判定。配置溯源默认折叠。

关联 Trace 的诊断面板展示已有固定 HTTP 运行阶段、截止标记、五个阶段计时，以及版本 1 的完整启动细分。缺失或无效数据保持“未记录”，不补零、不累加重叠时长、不展示任意私有字段。这只覆盖当前有界 HTTP 诊断合同，不能推断所有 MCP、Kagent 或业务工具都有相同观测能力。

## 证据关联与边界

工作流详情来自既有原执行 GET，不从当前流程设计反推历史配置。实例与策略决定使用步骤记录。新增“执行配置溯源”读取原提交快照里的节点版本，并为新 Runtime 步骤记录派发前选中的实例、ActorTemplate、原部署版本和镜像摘要；旧执行缺失这些记录时保持未记录，不从当前部署推算。节点版本与部署版本分别展示，绑定记录也不等于已执行成功。完整约定见[执行配置溯源](EXECUTION_CONFIGURATION.md)。

观测通过新增的原执行分页接口读取，不限登记时间。通用任务与控制节点按原执行外键关联，AX 按原任务保存的工作流/运行编号及任务主键关联。不会按 Agent、时间邻近或编号前缀关联，也不自行生成 Trace。服务端校验详情归属，前端再次核对执行、操作编号与入口类型；平台控制节点的登记编号不会被当作实际遥测 Trace 提供跳转。

每页20条，可继续加载更早登记；失败保留已读页与原游标，刷新从头读取。游标绑定原执行，按登记ID降序翻页，不是跨请求的冻结快照；刷新可读取新登记或更新后的状态。切换执行/身份/权限、刷新与卸载均会丢弃迟到响应。没有可见登记不等于没有执行、没有费用或观测齐全；历史记录不会在读取时补登记。用量未确认显示“未确认”，没有预占记录时不推断为零费用或已结算。完整约定见[原执行观测分页](WORKFLOW_OBSERVATIONS.md)。

手机端依次展示短列表、状态与结果、步骤、上下文与证据。没有新增正文存储、浏览器持久缓存、权限规则、数据库迁移或依赖。

## 后续

常规 Runtime 节点已接入 [EAP_JSON_V1 结构化结果验收](STRUCTURED_RESULTS.md)。时间线分别展示原任务回执、结构验收和资源回收；不合格结果保留原文，但停止下游交接。旧执行缺少验收记录时不推断为通过，原文仍需内容权限。配置入口在工作流节点属性，团队计划编辑器尚未提供。

试运行聊天与独立 AX 的创建仍在原入口，查询已汇入执行目录。原执行证据分页和 Runtime 派发时配置溯源已实现；可复用模板、完整运行策略、提交时固定执行版本、AX 沙箱版本，以及计划/AX/独立聊天的结果契约仍待推进；持久审批恢复与检查点分支需要后端协议支持。Kagent 运行时的具体覆盖应以独立验收为准，不能由当前界面推断兼容。
