# 控制台逐页优化（2026-10-23）

目标是完成全部 24 个路由入口的一轮使用体验优化。每页记录桌面/手机检查、实际修改和验收证据；保留既有成熟布局。本轮已部署验收，详见[完整证据](evidence/console-pages-20261023/README.md)和[逐页截图](evidence/console-pages-20261023/screenshots.md)。此处“已验收”限于下述页面与交互范围。

## 设计与实现约定

受众为配置、运行和治理企业智能体的操作人员。页面首先回答“当前对象是什么、当前状态如何、下一步可以做什么”。沿用产品现有深色导航与浅色工作区，不引入新依赖或外部字体。

颜色：导航 `#0c1c2b`、画布 `#f4f6f8`、表面 `#ffffff`、正文 `#193246`、辅助文字 `#52697b`、强调 `#087f9a`。保留语义状态色。字体沿用 Aptos / PingFang SC / Noto Sans CJK SC；页标题24px、区块15px、正文14px、辅助13px，数字对齐。

```text
页面标题 + 一句任务说明             刷新 / 主要操作
页面分区（可用 Tab、Enter、Space）
当前状态 / 筛选条件
主要工作内容                       证据或详情
范围说明 / 次要配置（按需展开）

手机：标题 → 操作 → 换行分区 → 筛选 → 内容 → 证据
```

设计复核：大屏继续采用现有深色态势布局；工作台保留事项优先级；表格与列表按数据性质选择。减少重复的大色块、装饰渐变和重复标题，保留 UNKNOWN、权限及证据范围说明，不将未观测包装成正常。

组件责任：页面继续拥有 API、权限和编辑状态；新增分区导航仅负责展示选项和发出选择事件，不拥有业务状态。集中主题负责共用排版、响应式及焦点，独立大屏/登录使用自身作用域。单个页面的局部修正不触发无关状态重构。

使用 `frontend-design`、`web-design-guidelines`、`vue-best-practices`；[Vercel 指南](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)于2026-10-23读取。既有 [Impeccable 参考及设计规则](CONSOLE_VISUAL_DESIGN.md)保持。

## 基线发现（本轮已处理）

- 注册发现、运行观测、知识和成本四页用可点击标签充当分区切换，缺少原生键盘行为；统一为语义按钮并保留选择状态。
- 智能体创建和全局登录/搜索弹窗使用固定桌面宽度，需验证并约束窄屏宽度。
- 部分筛选输入只有占位提示，补足明确的可访问名称与必要的持久标签。
- 调度、异步任务、团队优化、覆盖定位等新页面与旧页面标题/间距/卡片密度不一致；按页面任务统一排版。
- 业务任务记录需要验证手机可读性及与 `/me` 一致的管理入口。

## 执行记录

2026-10-23 基线浏览器完成24路由×桌面/手机，共48次检查；无整体横向溢出、脚本异常或业务写请求。人工查看全部24页的代表截图后确认：手机任务表格难读、监控下拉框过窄、部分指标标签对比度不足，以及伦理页固定系数百分比与“已覆盖”文案不准确。

本轮实现包括四页原生分区导航、带标签的分页与筛选、两类任务手机记录、任务修改能力与并发/异步确认保护、弹窗宽度/层级、伦理读取失败和真实计数，以及页面标题/摘要密度统一。成熟页面保留主结构，通过共用组件和视觉回归检查。

首轮远程前端510项通过，类型检查发现当前Element Plus不支持确认框的`zIndex`选项；改用限定该确认框的遮罩样式，保留首次失败记录。首次候选构建/上线通过。浏览器先识别出抽屉展开动画导致的瞬时几何断言，记录0–400ms尺寸后按稳定状态检查；随后发现手机成本页切换“投入产出”后内容撑开网格。临时样式验证桌面/手机五分区通过，修正真实CSS并再次通过510项测试、类型及构建。candidate-2 完成四角色×24路由×1440/390屏宽共192次页面检查、172项交互和8次真实PKCE登录。人工截图随后发现监控手机筛选仍受局部样式覆盖；candidate-3 仅加强3处选择器，其他938份输入一致，并重新通过510项、类型及构建，补测8次监控和2次分页操作。未把前一镜像的192次检查冒称最终镜像重跑结果。
